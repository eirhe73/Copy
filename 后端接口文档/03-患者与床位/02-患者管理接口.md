# 02 · 患者管理接口

## 1. 模块概述

| 项 | 内容 |
|----|------|
| 页面名称 | 患者列表（`/#/patients`）、患者详情（`/#/patient/:id`）、患者登记（`/#/register`）、会诊门户医生登记（`meeting-portal.html#register`） |
| 核心功能 | 在治患者列表与阶段筛选、患者详情（时间轴/会诊/预警）、患者登记（证件识别、院前上报） |
| 涉及实体 | 患者（patient）、急救患者登记（emergency_patient） |
| 数据源 | `public/scenario.json` 的 `patients` 实体；急救登记表复用 02 §2.4 `emergency_patients` |

对应路由（`routes/meta.ts`）：`/patients`（在治患者、阶段筛选、检索与导出）、`/patient/:id`（临床时间轴、会诊记录、预警与处置）、`/register`（证件识别、基本信息、院前上报）。

---

## 2. 数据模型定义

患者档案表 `patients` 与急救患者登记表 `emergency_patients`（见《02-院前急救调度接口》§2.4）详见本文件最后「附录：建表语句」。这里先给出急救登记的核心字段映射：

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |
|---------|-----------|------|------|------|
| 姓名 | name | String | 是 | 患者姓名 |
| 性别 | gender | Integer | 是 | 0男1女 |
| 年龄 | age | Integer | 否 | 年龄 |
| 电话 | phone | String | 否 | 联系电话 |
| 主诉 | chief_complaint | String | 否 | 主诉 |
| 是否草稿 | is_draft | Integer | 是 | 1草稿 0已提交 |

## 3. 接口清单

### 3.1 急救医生快速登记（急诊患者）

| 项目 | 内容 |
|------|------|
| 接口名称 | 急救医生快速登记 |
| 请求方法 | POST |
| 请求路径 | `/api/v1/patients` |
| 接口描述 | 急救科医生少字段快速登记患者（可保存草稿） |
| 前端调用时机 | `#register` 页点击「提交」/「存草稿」 |
| 前端渲染对应 | 医生登记表单 |

**Body 参数：**

| 字段名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| name | String | 是 | 姓名 | 王秀兰 |
| gender | String | 是 | 性别 MALE/FEMALE | FEMALE |
| age | Integer | 否 | 年龄 | 45 |
| phone | String | 否 | 电话 | 13800001111 |
| chiefComplaint | String | 否 | 主诉 | 胸痛、出汗 |
| isDraft | Integer | 否 | 是否草稿（缺省 0） | 1 |

**请求示例：**

```http
POST /api/v1/patients HTTP/1.1
Authorization: Bearer {token}
Content-Type: application/json

{ "name": "王秀兰", "gender": "FEMALE", "age": 45, "phone": "13800001111", "chiefComplaint": "胸痛、出汗", "isDraft": 0 }
```

**响应示例（成功）：**

```json
{
  "code": 200,
  "message": "success",
  "data": { "patientId": "PAT-20261013-001", "isDraft": 0 }
}
```

**错误码：** 200 / 400（name 为空）/ 401。

### 2.1 患者档案表 `patients`

患者档案以 `public/scenario.json` 的 `state.patients` 为准设计（第二组 `FIELD-*`/`ER-*` 记录含完整字段）：核心为姓名/性别/年龄/证件/电话/主诉/阶段/机构/科室/责任医护/院前上报，建表语句统一见文末「附录：建表语句」。

| 前端展示 | 数据库字段 | 类型 | 必填 | 示例 | 说明 |
|---------|-----------|------|------|------|------|
| 患者编号 | patient_id | String | 是 | `FIELD-001` | 患者唯一业务编号 |
| 姓名 | name | String | 是 | `李建国` | 患者姓名 |
| 性别 | gender | TinyInt | 是 | `0` | 0男 1女 2未知 |
| 年龄 | age | Integer | 否 | `63` | 未核实可空 |
| 证件号 | id_card | String | 否 | `510***********0012` | 证件号（OCR 回填，规范设计） |
| 电话 | phone | String | 否 | `139****0101` | 脱敏显示 |
| 机构 | institution_id | String | 是 | `chuanshi` | 所属机构编号 |
| 科室 | department_id | String | 是 | `primary` | 所属科室编号 |
| 责任医护 | assigned_to | JSON | 否 | `["chuanshi-primary-doctor"]` | 责任医护编号数组 |
| 阶段 | stage | String | 是 | `admitted` | 见 §4.1 |
| 主诉 | chief_complaint | String | 否 | `胸痛伴出汗约 40 分钟` | 归一化主诉 |
| 症状 | symptoms | JSON | 否 | `["胸痛（非创伤）","呼吸困难"]` | 症状数组 |
| 备注 | notes | String | 否 | — | 备注 |
| 来源 | source | String | 是 | `manual` / `120` | 见 §4.2 |
| 来源记录号 | source_record_id | String | 否 | `MOBILE-J-FIELD-001` | 院前/移动端来源记录 |
| 院前上报 | prehospital | JSON | 否 | `{...}` | 院前上报明细，见 §2.4 |
| 会诊编号 | consultation_token | String | 否 | `xun-2026-0003` | 关联会诊 |
| 会诊医生 | consultation_doctor_id | String | 否 | `weiyuan-emergency-doctor` | 接诊医生编号 |
| 会诊申请号 | consultation_request_id | String | 否 | `CR-F-003` | 会诊申请编号 |
| 入科时间 | admitted_at | DateTime | 否 | — | 入科时间 |

> 床位归属：患者档案不冗余床号，由 `beds.patient_id = patients.patient_id` 反查（见《01-床位管理接口》§2.2）。

### 2.2 患者临床时间轴事件表 `patient_events`

时间轴事件取自 `scenario.json` 的 `state.events`（Mock 仅含 `registered` 一类，其余类型为规范设计），与 `state.clinicalNotes` 合并呈现。

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |
|---------|-----------|------|------|------|
| 事件编号 | event_id | String | 是 | 事件唯一编号 |
| 患者 | patient_id / patient_name | String | 是 | 患者编号与冗余姓名 |
| 事件类型 | type | String | 是 | 见 §4.3 |
| 发生时间 | at | DateTime | 是 | 事件时间 |
| 操作人 | actor_id | String | 否 | 操作人编号 |
| 描述 | note | String | 否 | 事件描述 |
| 作用范围 | scopes | JSON | 否 | `[{"institutionId","departmentId"}]` |
| 参与人 | user_ids | JSON | 否 | 相关医护编号数组 |

### 2.3 患者临床记录表 `clinical_notes`

临床记录取自 `scenario.json` 的 `state.clinicalNotes`（护理/检验/用药/评估四类），时间轴与事件合并按时间倒序展示。

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |
|---------|-----------|------|------|------|
| 记录编号 | note_id | String | 是 | 记录唯一编号 |
| 患者 | patient_id | String | 是 | 患者编号 |
| 类型 | kind | String | 是 | 见 §4.4 |
| 标题 | title | String | 是 | 记录标题 |
| 内容 | text | String | 是 | 正文 |
| 时间 | at | DateTime | 是 | 记录时间 |
| 记录人 | actor_id | String | 否 | 记录人编号 |

### 2.4 院前上报对象 `prehospital`

院前上报（`POST /api/v1/patients/pre-admission`）入参与 `patients.prehospital` 均为同一结构，字段取自 `scenario.json` 患者 `prehospital` 子对象：

| 前端展示 | 字段名 | 类型 | 必填 | 说明 |
|---------|-------|------|------|------|
| 病种分类 | category | String | 是 | 胸痛/卒中/创伤/其他 |
| 联系人 | contact | String | 否 | 联系人与患者关系 |
| 联系电话 | phone | String | 否 | 联系电话 |
| 现场地址 | address | String | 是 | 事发/现场地址 |
| 主诉 | complaint | String | 是 | 主诉描述 |
| 症状 | symptoms | String[] | 否 | 症状数组 |
| 发病时长 | onset | String | 否 | 30分钟内/30分钟至2小时/2小时以上 |
| 意识 | consciousness | String | 否 | 意识状态 |
| 呼吸 | breathing | String | 否 | 呼吸状态 |
| 活动能力 | mobility | String | 否 | 活动能力 |
| 专科特点 | specialty | String[] | 否 | 专科重点关注 |
| 既往史 | history | String[] | 否 | 既往史 |
| 过敏史 | allergies | String | 否 | 过敏史 |
| 上报时间 | at | DateTime | 否 | 上报时间 |

### 4.1 患者阶段 `stage`

| `admitted` | 在治 | 已入科/在院治疗 |
| `transfer-requested` | 转诊中 | 已申请转诊，待接收 |
| `in-transit` | 转运中 | 转运途中 |

## 5. 交互与边界说明

- **阶段流转**：`registered → consulting / accepted → admitted → (transfer-requested → in-transit → accepted) → local-closed`；由登记、会诊、转诊、出院等动作驱动，不允许非法跳跃。
- **证件脱敏**：`phone`/`idCard` 默认脱敏返回（`139****0101` 形式）；详情授权可见部分明文字段。
- **OCR 幂等**：OCR 仅回填登记表单，不直接入库；由「提交登记」确认后落库。
- **导出上限**：`GET /patients/export` 默认导出当前筛选全量，单次上限 10000 条（超过提示缩小筛选范围）。
- **院前上报联动**：`pre-admission` 成功后按病情（胸痛/卒中）可联动绿色通道与转诊流程，见《03-转诊协同接口》。

---

## 6. 前端对接注意事项

- **筛选状态保持**：`#patients` 阶段筛选与关键字经 URL query 保持，刷新不丢失。
- **时间轴排序**：临床记录与事件按 `at` 倒序合并返回，前端按 `category` 区分图标。
- **空数据**：无会诊/预警时对应 `list` 返回空数组；`bed` 为 `null` 表示未分配床位。
- **证件识别失败**：OCR 识别失败或图片质量差时，前端提示「识别失败，请手动填写」。
