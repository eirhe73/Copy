## 2. 数据模型定义

### 2.1 转运任务表 `transfers`

转诊业务实体（字段为规范设计，无独立 Mock；演示链路见 `grassroots-demo.json` 的三步流程「下级上报 → 县院会诊 → 转诊上行」）。上转/下转、华西绿色通道、响应时长统计均由本表 + 时间戳字段推导。

| 前端展示 | 数据库字段 | 类型 | 必填 | 示例 | 说明 |
|---------|-----------|------|------|------|------|
| 转诊编号 | transfer_id | String | 是 | `TRF-20261013-001` | 转诊任务唯一编号 |
| 患者 | patient_id / patient_name | String | 是 | `FIELD-002` / `王秀兰` | 关联患者与冗余姓名 |
| 方向 | direction | TinyInt | 是 | `0` | 0 上转 1 下转 |
| 来源机构/科室 | source_institution_id / source_department_id | String | 是 | `chuanshi` / `primary` | 转出端 |
| 目标机构/科室 | target_institution_id / target_department_id | String | 是 | `huaxi` / `icu` | 接收端 |
| 状态 | status | TinyInt | 是 | `0` | 见 §4.2 |
| 绿色通道 | green_channel | TinyInt(1) | 否 | `1` | 是否绿色通道 |
| 通道类型 | channel_type | String | 否 | `chest_pain` | 华西绿色通道类型，见 §4.3 |
| 转诊原因 | reason | String | 否 | `胸痛待进一步介入治疗` | 转诊原因/诊断 |
| 转运车辆 | transport_vehicle_id | String | 否 | `AMB-1` | 关联救护车 |
| 发起人 | created_by | String | 否 | `chuanshi-primary-doctor` | 发起人编号 |
| 申请时间 | started_at | DateTime | 是 | — | 发起转诊时间 |
| 接收时间 | accepted_at | DateTime | 否 | — | 接收确认时间 |
| 到院时间 | arrived_at | DateTime | 否 | — | 到达接收方时间 |
| 完成时间 | completed_at | DateTime | 否 | — | 转诊完成时间 |

```sql
CREATE TABLE `transfers` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `transfer_id` VARCHAR(32) NOT NULL COMMENT '转诊编号，如 TRF-20261013-001',
  `patient_id` VARCHAR(32) NOT NULL COMMENT '患者编号',
  `patient_name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '患者姓名（冗余）',
  `direction` TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '方向：0上转 1下转',
  `source_institution_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '来源机构编号',
  `source_department_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '来源科室编号',
  `target_institution_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '目标机构编号',
  `target_department_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '目标科室编号',
  `status` TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '状态：见状态枚举',
  `green_channel` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '是否绿色通道：1是 0否',
  `channel_type` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '华西绿色通道类型',
  `reason` VARCHAR(255) NOT NULL DEFAULT '' COMMENT '转诊原因/诊断',
  `transport_vehicle_id` VARCHAR(32) NULL DEFAULT NULL COMMENT '转运车辆编号',
  `created_by` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '发起人编号',
  `started_at` DATETIME NOT NULL COMMENT '发起转诊时间',
  `accepted_at` DATETIME NULL DEFAULT NULL COMMENT '接收确认时间',
  `arrived_at` DATETIME NULL DEFAULT NULL COMMENT '到院时间',
  `completed_at` DATETIME NULL DEFAULT NULL COMMENT '完成时间',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_transfer_id` (`transfer_id`),
  KEY `idx_patient` (`patient_id`),
  KEY `idx_status_started` (`status`, `started_at`),
  KEY `idx_target` (`target_institution_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='转运任务表';
```

索引说明：
- `uk_transfer_id`：单条转诊按编号直查。
- `idx_status_started`：转诊列表按状态 + 时间排序。
- `idx_target`：华西绿色通道按接收机构聚合。

### 3.3 发起转诊

| 项目 | 内容 |
|------|------|

| 前端渲染对应 | 转诊创建表单 |

**Body 参数：**

| 字段名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| patientId | String | 是 | 患者编号 | FIELD-002 |
| direction | String | 是 | 方向 UP/DOWN | UP |
| sourceInstitutionId | String | 是 | 来源机构编号 | chuanshi |
| sourceDepartmentId | String | 否 | 来源科室编号 | primary |
| targetInstitutionId | String | 是 | 目标机构编号 | huaxi |
| targetDepartmentId | String | 否 | 目标科室编号 | icu |

| channelType | String | 否 | 通道类型 | stroke |
| reason | String | 否 | 转诊原因/诊断 | 卒中绿色通道上行 |

**请求示例：**

```http

Content-Type: application/json

{
  "patientId": "FIELD-002",
  "direction": "UP",

  "sourceDepartmentId": "primary",
```

## 4. 状态与枚举值

### 4.1 转诊方向 `direction`

| 存储值 | 显示文本 | 说明 |
|-------|---------|------|
| `UP` | 上转 | 下级 → 上级（含华西） |
| `DOWN` | 下转 | 上级 → 下级 |

### 4.2 转诊状态 `status`

| 存储值 | 显示文本 | 说明 |
|-------|---------|------|
| `REQUESTED` | 待接收 | 已发起，等待接诊方确认 |
| `ACCEPTED` | 已接收 | 接诊方确认接收 |
| `IN_TRANSIT` | 转运中 | 转运车辆在途 |
| `ARRIVED` | 到院 | 到达接收方 |
| `COMPLETED` | 已完成 | 交接完成 |
| `REJECTED` | 已拒绝 | 接收方拒绝 |

> 状态流转：`REQUESTED → ACCEPTED → IN_TRANSIT → ARRIVED → COMPLETED`；`REQUESTED → REJECTED` 为终态。

### 4.3 华西绿色通道类型 `channel_type`

| 存储值 | 显示文本 |
|-------|---------|
| `chest_pain` | 胸痛中心 |
| `stroke` | 卒中中心 |
| `trauma` | 创伤中心 |
| `critical_pregnant` | 危重孕产妇 |
| `neonatal` | 危重新生儿 |

## 5. 交互与边界说明

- **响应时长口径**：`response_minutes = accepted_at - started_at`（分钟）；仅对已接收（含其后状态）任务计入。
- **绿色通道联动**：胸痛/卒中等院前上报（见《02-患者管理接口》`pre-admission`）可自动生成 `green_channel=true` 的转诊任务。
- **状态合法性**：后端维护状态机（流转图见 §4.2），非法跳跃返回 400。
- **演示链**：`grassroots-demo.json` 的三步为配置类演示数据，与 `transfers` 真实任务分离，前端根据 `patientName` 高亮对应行（见 `grassroots-demo-enhance.js`）。

---

## 6. 前端对接注意事项

- **行高亮**：`grassroots-demo-enhance.js` 会在转诊列表中按 `transferDemo.patientName` 高亮演示行并加徽标，接口需返回 `patientName` 供匹配。
- **步骤条**：`/transfers`、`/consultations` 页顶部演示步骤条读取 `/api/grassroots-demo.json`，与真实转诊接口相互独立。
- **空数据**：无转诊时 `list` 返回空数组；趋势无数据时 `trend` 为空数组。
- **状态文案**：前端按 `directionLabel`/`statusLabel` 展示，色值按 `UP`（上行，主色）与 `DOWN`（下行，次色）区分。
