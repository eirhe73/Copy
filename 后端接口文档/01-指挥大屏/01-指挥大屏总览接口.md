# 01 · 指挥大屏总览接口

## 1. 页面/模块概述

| 项 | 内容 |
|----|------|
| 页面名称 | 一体化指挥中心首页（主 SPA `index.html`，Hash 路由 `/#/`） |
| 核心功能 | 县域地图 + 救护车实时点位、今日急救事件 / 在途转运 / 预警待处置、机构床位占用与 ICU 远程单元状态、24 小时县域智慧重症事件趋势 |
| 涉及实体 | 聚合统计 + 看板布局偏好（`dashboard_layouts`）；聚合引用 `collab_nodes`、`vehicles`、`emergency_events`、床位/预警等既有实体 |
| 数据源 | `public/scenario.json`（`state.patients/staff/beds/alerts/events/clinicalNotes`、顶层 `vehicles/measurements/trends`）、`public/api/dispatch-live.json`、`public/api/gis-collab.json`、`public/api/vehicles-gps.json` |

前端功能点（[`routes/meta.ts`](../huaxi-command-center/src/routes/meta.ts) 首页 `modules`）：

- `县域地图`：顶部地图区域，复用县域协同节点 + 在途车辆点位（数据同 GIS 大屏）。
- `急救调度概览`：今日出警事件卡片与状态分布（数据同 `dispatch-live.json`）。
- `实时事件流`：滚动播报患者登记 / 转运 / 预警等业务事件（数据同 `scenario.state.events`）。
- `KPI 指标墙`：核心指标数字墙（今日急救、在途转运、预警待处置、床位占用率等）。

> 说明：首页当前为 `HomePage` 占位（仅列功能点，无真实图表渲染），但四个功能点的数据模型在 `scenario.json` / Mock 中真实存在，故本组接口按「首页一次聚合 + 各面板独立子接口」设计，字段直接对齐数据源。**看板布局（`dashboard/layout`）为纯规范设计（前端为占位页，无真实交互）。**

## 2. 数据模型定义

### 2.1 看板布局偏好表 `dashboard_layouts`

> 仅本业务域新增实体；其余聚合数据均来自既有表，不重复建表。`county-map` 复用 `collab_nodes` / `collab_links`（见 [00-GIS协同态势接口](00-GIS协同态势接口.md) §2），`dispatch-overview` 复用 `emergency_events` / `vehicles`（见 [02-院前急救调度接口](02-院前急救调度接口.md) §2）。

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |
|---------|-----------|------|------|------|
| 布局作用域 | scope | String | 是 | `default` 全局 / `role` 角色 / `user` 个人 |
| 归属用户 | user_id | BigInt | 否 | `scope=user` 时必填；否则为 NULL |
| 布局配置 | layout | JSON | 是 | 面板显隐 / 顺序 / 尺寸 / 锁定 |
| 版本号 | version | Integer | 是 | 乐观锁版本 |

```sql
CREATE TABLE `dashboard_layouts` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `scope` VARCHAR(16) NOT NULL DEFAULT 'default' COMMENT '作用域：default全局/role角色/user个人',
  `role_key` VARCHAR(32) NULL DEFAULT NULL COMMENT 'scope=role 时的角色键，如 doctor/director',
  `user_id` BIGINT UNSIGNED NULL DEFAULT NULL COMMENT 'scope=user 时的用户ID',
  `layout` JSON NOT NULL COMMENT '面板布局配置（显隐/顺序/尺寸/锁定）',
  `version` INT UNSIGNED NOT NULL DEFAULT 1 COMMENT '乐观锁版本号',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_scope_owner` (`scope`, `role_key`, `user_id`),
  KEY `idx_user_id` (`user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='指挥大屏看板布局偏好表';
```

索引说明：
- `uk_scope_owner`：同一作用域 + 所有者（角色或用户）只保留一份布局，读/写按此键定位。
- `idx_user_id`：按用户反查其个人布局。

`layout` JSON 结构约定：

```json
{
  "panels": [
    { "key": "map", "title": "县域地图", "visible": true, "order": 1, "span": 8, "locked": false },
    { "key": "dispatch", "title": "急救调度概览", "visible": true, "order": 2, "span": 4, "locked": false },
    { "key": "eventStream", "title": "实时事件流", "visible": true, "order": 3, "span": 4, "locked": false },
    { "key": "kpi", "title": "KPI 指标墙", "visible": true, "order": 4, "span": 8, "locked": false }
  ],
  "fullscreen": false,
  "theme": "light"
}
```

| 项目 | 内容 |
|------|------|
| 接口名称 | 一体化指挥总览 |

| 说明 | **前端为占位页，字段为规范设计** |

**Body 参数：**

| 字段名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| scope | String | 否 | 作用域，缺省 user | user |
| layout | Object | 是 | 布局配置，结构见 §2.1 | { "panels": [...] } |
| version | Integer | 否 | 乐观锁版本号，校验冲突 | 1 |

**请求示例：**

```http
POST /api/v1/dashboard/layout HTTP/1.1
Authorization: Bearer {token}
Content-Type: application/json

{
  "scope": "user",
  "layout": {
    "panels": [
      { "key": "map", "title": "县域地图", "visible": true, "order": 1, "span": 8, "locked": false },
      { "key": "kpi", "title": "KPI 指标墙", "visible": true, "order": 4, "span": 8, "locked": false }
    ],
    "fullscreen": false,
    "theme": "light"
  },
  "version": 1
}
```

**响应示例（成功）：**

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "scope": "user",
    "version": 2
  }
}
```

**错误码：**

| code | 含义 |
|------|------|
| 200 | 成功 |
| 400 | 参数校验失败（如 layout 缺少 panels） |
| 401 | 未认证或 Token 失效 |
| 409 | 版本冲突（version 落后于服务端，需重新读取后保存） |

## 5. 交互与边界说明

- **聚合与拆分**：`overview` 为首页首屏聚合（一次拉取）；`kpi` / `event-stream` / `dispatch-overview` / `county-map` 为面板独立刷新接口。前端首屏用 `overview`，后续每面板各自轮询，避免整页重复拉取。
- **布局缓存**：读写按 `scope` 三级回退（user → role → default）；`scope=user` 未配置时返回角色布局，角色未配置返回全局默认。
- **事件流增量**：`cursor` 为本次最后一条事件 id，服务端按 `id` 排序 + 时间倒序返回其后新增，前端追加去重。
- **性能**：`overview` / `kpi` / `dispatch-overview` / `county-map` 均为大屏高频轮询（5~15s），建议加 3~5s 轻量缓存；各聚合统计走既有索引（`emergency_events.idx_status_started`、`collab_nodes.idx_region_tier`）。

## 6. 前端对接注意事项

- **首屏体验**：`overview` 未返回前建议骨架屏；各子面板 loading 独立。
- **空数据**：无事件流时显示空状态；地图无车辆时不显示车辆图例。
- **布局版本冲突（409）**：提示「布局已被其他端修改，已刷新为最新」，并重新读取后再保存。
- **错误提示**：聚合接口失败提示「大屏数据加载失败」，子面板失败静默重试。
