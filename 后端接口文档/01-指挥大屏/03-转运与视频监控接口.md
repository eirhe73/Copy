# 03 · 转运与视频监控接口

## 1. 页面/模块概述

| 项 | 内容 |
|----|------|
| 页面名称 | 转运任务详情（`/#/transport/:id`）、视频监控（`/#/monitoring`） |
| 核心功能 | 转运途中车载监护（实时体征）、轨迹回放、到院交接清单；远程 ICU 画面多路监控、单路拉流、云台控制 |
| 涉及实体 | 转运任务（`transfers`）、车载体征时序（`transfer_vitals`）、监控流台账（`monitoring_streams`）；复用 `vehicle_locations`（轨迹）、`dispatch_handovers`（交接清单） |
| 数据源 | `public/scenario.json`（`mobile.dispatches`、`mobile.journeys`、`vehicles[].route`、`measurements`）、`public/assets/video-placeholder-enhance.js`（监控占位） |

前端功能点（[`routes/meta.ts`](../huaxi-command-center/src/routes/meta.ts)）：

- `/#/transport/:id` 转运任务详情（`modules`: 车载监护 / 交接清单 / 轨迹回放）。
- `/#/monitoring` 视频监控（`modules`: 远程 ICU 画面 / 云台控制 / 多路监控切换）。

> 说明：转运详情页与视频监控页当前均为 `PageScaffold` 占位页。其中**车载监护**（`measurements`）、**轨迹回放**（`vehicles[].route`、`vehicle_locations`）字段有真实数据源，可直接对齐；**交接清单、监控流列表、单路拉流、云台控制**前端为占位页（`video-placeholder-enhance.js` 统一显示「演示未接」），字段为规范设计。

## 2. 数据模型定义

### 2.1 转运任务表 `transfers`

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |
|---------|-----------|------|------|------|
| 转运编号 | transfer_no | String | 是 | 任务编号，如 DISP-0001 |
| 患者 | patient_id / patient_name | String | 是 | 关联患者 |
| 车辆 | vehicle_id | String | 否 | 关联救护车编号 |
| 状态 | status | Integer | 是 | 复用全局状态枚举（DISPATCHING/ON_SCENE/RETURNING） |
| 来源机构 | from_institution_id | String | 是 | 转出机构 |
| 目标机构 | to_institution_id | String | 是 | 接收机构 |
| 医生 / 护士 | doctor_id / nurse_id | String | 否 | 随车医护 |
| 开始时间 | started_at | DateTime | 否 | 转运开始 |
| 到院 / 交接时间 | arrived_at / handover_at | DateTime | 否 | 到院与交接完成 |
| 里程碑 | milestones | JSON | 否 | `[{key,at,by},...]` |

```sql
CREATE TABLE `transfers` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `transfer_no` VARCHAR(32) NOT NULL COMMENT '转运任务编号，如 DISP-0001',
  `patient_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '患者编号',
  `patient_name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '患者姓名',
  `vehicle_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '车辆编号',
  `status` TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '状态：复用全局事件/车辆状态枚举',
  `from_institution_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '来源机构编号',
  `to_institution_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '目标机构编号',
  `doctor_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '随车医生账号',
  `nurse_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '随车护士账号',
  `started_at` DATETIME NULL DEFAULT NULL COMMENT '转运开始时间',
  `arrived_at` DATETIME NULL DEFAULT NULL COMMENT '到院时间',
  `handover_at` DATETIME NULL DEFAULT NULL COMMENT '交接完成时间',
  `milestones` JSON NULL COMMENT '里程碑：[{key,at,by},...]',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_transfer_no` (`transfer_no`),
  KEY `idx_patient` (`patient_id`),
  KEY `idx_vehicle` (`vehicle_id`),
  KEY `idx_status` (`status`),
  KEY `idx_to_institution` (`to_institution_id`, `status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='院前/院间转运任务表';
```

索引说明：
- `uk_transfer_no`：任务编号唯一，支撑 `/transfers/{id}` 及监护/轨迹/交接按编号查询。
- `idx_patient` / `idx_vehicle`：患者 ↔ 车辆 ↔ 转运关联查询。
- `idx_to_institution`：接收机构按状态汇总（绿色通道 / 到院准备）。

> 转运任务状态 `status` 复用 [00-总览 README](00-总览/README.md) §3.1 全局枚举（`DISPATCHING`/`ON_SCENE`/`RETURNING`）；「到院」与「交接完成」两个终态通过 `arrived_at`/`handover_at` 时间戳 + `milestones` 键（`at-hospital`、`onboard`、`on-scene`、`accepted`）表达，不新增冲突枚举。

### 2.2 车载体征时序表 `transfer_vitals`

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |
|---------|-----------|------|------|------|
| 转运编号 | transfer_no | String | 是 | 关联 transfers.transfer_no |
| 患者 | patient_id | String | 是 | 关联患者编号 |
| 心率 | heart_rate | Integer | 否 | 次/分 |
| 血氧 | spo2 | Integer | 否 | % |
| 呼吸 | resp | Integer | 否 | 次/分 |
| 体温 | temp | Decimal(4,1) | 否 | ℃ |
| 收缩压 / 舒张压 | systolic / diastolic | Integer | 否 | mmHg |
| NEWS 评分 | news | Integer | 否 | 院前评分 |
| 采集时间 | captured_at | DateTime | 是 | 上报时间 |

```sql
CREATE TABLE `transfer_vitals` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `transfer_no` VARCHAR(32) NOT NULL COMMENT '转运任务编号',
  `patient_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '患者编号',
  `heart_rate` INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '心率 次/分',
  `spo2` TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '血氧 %',
  `resp` TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '呼吸 次/分',
  `temp` DECIMAL(4,1) NOT NULL DEFAULT 0 COMMENT '体温 ℃',
  `systolic` INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '收缩压 mmHg',
  `diastolic` INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '舒张压 mmHg',
  `news` TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT 'NEWS 评分',
  `captured_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '采集上报时间',
  PRIMARY KEY (`id`),
  KEY `idx_transfer_captured` (`transfer_no`, `captured_at`),
  KEY `idx_patient_captured` (`patient_id`, `captured_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='车载体征时序表';
```

索引说明：
- `idx_transfer_captured`：车载监护按任务 + 时间拉取最新体征与曲线。
- `idx_patient_captured`：患者维度的体征时序（可复用于重症体征曲线）。

### 2.3 监控流台账表 `monitoring_streams`

> 前端为占位页，字段为规范设计。

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |
|---------|-----------|------|------|------|
| 流编号 | stream_id | String | 是 | 监控点唯一编号 |
| 名称 | name | String | 是 | 画面名称 |
| 类型 | kind | String | 是 | `icu` 重症 / `bed` 床旁 / `vehicle` 车内 |
| 机构 / 科室 | institution_id / department_id | String | 否 | 归属 |
| 床位 / 车辆 | bed_id / vehicle_id | String | 否 | 关联对象 |
| 在线状态 | online | Boolean | 是 | 拉流可用性 |
| 是否支持云台 | ptz_enabled | Boolean | 是 | 是否支持 PTZ 控制 |

```sql
CREATE TABLE `monitoring_streams` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `stream_id` VARCHAR(32) NOT NULL COMMENT '监控点编号，如 CAM-ICU-01',
  `name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '画面名称',
  `kind` VARCHAR(16) NOT NULL DEFAULT 'bed' COMMENT '类型：icu重症/bed床旁/vehicle车内',
  `institution_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '机构编号',
  `department_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '科室编号',
  `bed_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '关联床位编号',
  `vehicle_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '关联车辆编号',
  `online` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '在线：0离线1在线',
  `ptz_enabled` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '支持云台：0否1是',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_stream_id` (`stream_id`),
  KEY `idx_kind_inst` (`kind`, `institution_id`),
  KEY `idx_bed` (`bed_id`),
  KEY `idx_vehicle` (`vehicle_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='远程监控流台账表';
```

索引说明：
- `uk_stream_id`：监控点唯一，支撑单路拉流按编号定位。
- `idx_kind_inst`：按类型 + 机构过滤多路监控列表。
- `idx_bed` / `idx_vehicle`：床旁 / 车内监控反查关联对象。

> 轨迹回放复用 `vehicle_locations`（DDL 见 [02-院前急救调度接口](02-院前急救调度接口.md) §2.2，其 `idx_vehicle_located(vehicle_id, located_at)` 即支持按时间拉取历史轨迹）；到院交接清单复用 `dispatch_handovers`（DDL 见 [02-院前急救调度接口](02-院前急救调度接口.md) §7.1）。

| 项目 | 内容 |
|------|------|
| 接口名称 | 车载监护 |
| 请求方法 | GET |
| 请求路径 | `/api/v1/transfers/{transferNo}/monitor` |
| 接口描述 | 返回转运途中患者实时体征（最新值 + 近 N 条时序）与车辆/患者摘要 |

## 5. 交互与边界说明

- **体征时序**：`monitor` 一次返回最新值 + 近 N 条；高负载场景可改为 SSE / WebSocket 推送，此前端占位页为轮询。
- **轨迹点精度**：经纬度保留 6 位小数；`from`/`to` 未传时返回全量（建议服务端限制最大点数，如 1000，超出抽样）。
- **交接清单 vs 到院交接**：`handover-list`（本文件 3.3）只读，数据由 [02-院前急救调度接口](02-院前急救调度接口.md) `POST /api/v1/dispatch/handover` 写入，二者共用 `dispatch_handovers` 表。
- **拉流凭证**：`streamUrl` / `playToken` 应短时有效（expiresAt），前端过期后自动重拉 `/streams/{id}` 换取新凭证。
- **云台边界**：不支持 PTZ 的流（`ptzEnabled=false`）下发指令返回 409；连续方向键应节流，配合 `stop` 结束动作，避免指令风暴。

## 6. 前端对接注意事项

- **占位页兜底**：监控画面 / 车内监控在正式环境未接摄像头时显示「演示未接」占位（`video-placeholder-enhance.js`），后端接口仍按规范返回结构，前端据此判断 `online` / `streamUrl` 是否存在。
- **loading**：画面加载前显示骨架/占位，`streamUrl` 就绪后再初始化播放器。
- **轮询**：`monitor` 建议 5~10s 轮询体征；`streams` 建议 15s 刷新在线状态。
- **错误提示**：拉流失败提示「画面连接失败，请稍后重试」；云台无响应提示「云台无响应」。
- **空数据**：无体征时曲线区显示空状态；无监控流时网格显示空状态。
