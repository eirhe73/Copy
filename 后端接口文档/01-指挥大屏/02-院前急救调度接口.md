# 02 · 院前急救调度接口

## 1. 页面/模块概述

| 项 | 内容 |
|----|------|
| 页面名称 | 120 急救调度（`dispatch.html`） |
| 核心功能 | 实时出警看板、急救事件列表、救护车台账、车上就地患者登记 |
| 涉及实体 | 急救事件（emergency_event）、救护车（vehicle）、急救患者登记（emergency_patient） |
| 数据源 | `public/api/dispatch-live.json`、`public/api/dispatch-ambulances.json`、`public/api/vehicles-gps.json` |

前端 4 个 Tab（[App.vue](../huaxi-command-center/src/dispatch-hub/App.vue)）：

- `#live` 实时出警：左侧事件卡片 → 选中后右侧显示车辆看板 + 就地登记表单；10s 轮询。
- `#events` 急救事件：事件列表，支持跳「出警处理」「登记」。
- `#ambulances` 救护车列表：车辆台账，点击查看车辆看板。
- `#register` 患者登记：医生一屏录入（支持保存草稿 / 提交 / 发起会诊）。

## 2. 数据模型定义

### 2.1 救护车台账表 `vehicles`

| 前端展示 | 数据库字段 | 类型 | 必填 | 示例 | 说明 |
|---------|-----------|------|------|------|------|
| 车牌 / ID | plate / vehicle_id | String | 是 | `演示001` / `AMB-1` | 牌照与车辆编号 |
| 所属 | org | String | 是 | `威远县120` | 所属单位 |
| 绑定医院 | bound_hospital | String | 是 | `威远县人民医院` | 绑定医院 |
| 班组 | crew | String | 是 | `张医生 / 李护士` | 随车班组 |
| 状态 | status | Integer | 是 | `1` | 见枚举 |
| 关联事件 | current_event_id | String | 否 | `EVT-20261012-01` | 当前任务事件 |

```sql
CREATE TABLE `vehicles` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `vehicle_id` VARCHAR(32) NOT NULL COMMENT '车辆编号，如 AMB-1',
  `plate` VARCHAR(16) NOT NULL DEFAULT '' COMMENT '车牌号',
  `org` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '所属单位，如 威远县120',
  `bound_hospital` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '绑定医院',
  `crew` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '随车班组',
  `status` TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '状态：0待命1出警中2现场处置3返院途中',
  `current_event_id` VARCHAR(32) NULL DEFAULT NULL COMMENT '当前关联急救事件编号',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_vehicle_id` (`vehicle_id`),
  KEY `idx_status` (`status`),
  KEY `idx_current_event` (`current_event_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='救护车台账表';
```

### 2.3 急救事件表 `emergency_events`

| 前端展示 | 数据库字段 | 类型 | 必填 | 示例 | 说明 |
|---------|-----------|------|------|------|------|

```sql
CREATE TABLE `emergency_events` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `event_id` VARCHAR(32) NOT NULL COMMENT '事件编号，如 EVT-20261012-01',
  `task120_id` VARCHAR(32) NOT NULL COMMENT '120 任务号，如 120-WY-88421',
  `level` TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '等级：0重症1急症2一般',
  `chief_complaint` VARCHAR(255) NOT NULL DEFAULT '' COMMENT '主诉',
  `pickup_address` VARCHAR(128) NOT NULL DEFAULT '' COMMENT '接车地址',
  `destination` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '目标医院',
  `vehicle_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '车辆编号',
  `vehicle_plate` VARCHAR(16) NOT NULL DEFAULT '' COMMENT '车牌',
  `status` TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '状态：见状态枚举',
  `started_at` DATETIME NOT NULL COMMENT '出警时间',
  `eta_hospital_minutes` INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '预计到院分钟',
  `eta_patient_minutes` INT UNSIGNED NULL DEFAULT NULL COMMENT '预计到患者分钟',
  `score_plan` VARCHAR(255) NOT NULL DEFAULT '' COMMENT '院前评分方案',
  `treat_plan` TEXT NULL COMMENT '救治方案',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_event_id` (`event_id`),
  UNIQUE KEY `uk_task120_id` (`task120_id`),
  KEY `idx_status_started` (`status`, `started_at`),
  KEY `idx_vehicle` (`vehicle_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='急救事件表';
```

索引说明：
- `uk_event_id` / `uk_task120_id`：事件与 120 工单一一对应，且支持「按 task120Id 回填登记」。
- `idx_status_started`：实时出警看板按状态 + 时间排序。
- `idx_vehicle`：事件 ↔ 车辆关联查询。

## 5. 交互与边界说明

- **二次确认**：患者登记正式提交后建议前端确认（演示未做）；删除登记为软删除（`deleted_at`）。
- **字段联动**：从出警/车辆页进入登记时，`eventId`/`task120Id`/`vehicleId`/`vehiclePlate`/`chiefComplaint` 由上个页面带入（URL query / hash 传递），后端需校验这些关联字段合法（事件/车辆存在）。
- **表单校验**：`name` 必填（前端已 `required`，提交前 trim 校验）；`age` 为数字、0-150；`phone` 为可空手机号。
- **草稿 vs 提交**：同一任务号（`task120Id`）再次登记时，前端会回填上次草稿；后端对同一 `task120Id` 的正式提交应支持更新（幂等，按 task120_id upsert）。
- **状态流转**：事件状态随出车生命周期变化（出警中 → 现场处置 → 返院途中），由调度端更新。

---

## 6. 前端对接注意事项

- **生命周期**：`#live` 页 `onMounted` 加载 + 10s 轮询，`onUnmounted` 停止轮询。
- **loading**：登记提交按钮加 loading；姓名为空时提示「请填写姓名后再提交」。
- **错误提示**：提交失败提示「提交失败，请稍后重试」；草稿保存失败提示「草稿保存失败」。
- **空数据**：无进行中事件时显示空状态；无关联事件时车辆「关联事件」列显示 `—`。

### 7.1 到院交接记录表 `dispatch_handovers`

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |

```sql
  `patient_name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '患者姓名',
  `from_staff_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '交接方账号',
  `from_staff_name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '交接方姓名',
  `to_staff_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '接收方账号',
  `to_staff_name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '接收方姓名',
  `to_dept` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '接收科室',
  `items` JSON NULL COMMENT '交接明细：[{key,title,done,note},...]',
  `signature` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '签收标记',
  `handover_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '交接时间',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_handover_no` (`handover_no`),
  KEY `idx_transfer` (`transfer_no`),
  KEY `idx_event` (`event_id`),
  KEY `idx_task120` (`task120_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='到院交接记录表';
```

索引说明：
- `uk_handover_no`：交接单唯一，支撑按单号查询。
- `idx_transfer`：按转运任务拉取交接清单（对应 [03-转运与视频监控接口](03-转运与视频监控接口.md) §3.3 `handover-list`）。
- `idx_event` / `idx_task120`：事件 / 120 工单维度反查交接记录。
