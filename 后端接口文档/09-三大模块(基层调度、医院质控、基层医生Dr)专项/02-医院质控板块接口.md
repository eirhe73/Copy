# 医院质控板块 · 接口文档（完整版）

> 版本：v2.0  
> 编制日期：2026-10-13  
> 范围：产品 IA「4 医院质控」4.1～4.3  
> 实现代码：`QcStandardController`、`QcIssueController`、`SlaRecordController`  
> 基础路径：`/api/v1`  
> Mock 契约：`public/api/qc-standards.json`、`public/api/qc-sla.json`（与 summary / sla-records index 对齐）

---

## 1. 板块与子模块

| 编号 | 子模块 | 前端入口 | 后端接口 |
|------|--------|----------|----------|
| 4.1 | 智能监控 | `/#/medical-quality` 环节时限块；`qc-sla-enhance.js` | `GET /sla-records`（规则+台账）；可叠加 `qc-issues?overdue=1` |
| 4.2 | 质控统计 | `/#/medical-quality/reports`；会诊门户质控页 | `GET /qc-issues-report`；`GET /qc-standards/summary`；`GET /qc-issues` |
| 4.3 | 质控提醒 | 看板超期行、SLA 超时标记 | `sla-records` 的 `overtime`；`qc-issues?overdue=true` |

前端整改台账表格仍部分来自 **scenario 演示存档**；后端 `qc-issues` 已可独立驱动报表与导出。

---

## 2. 响应约定

与基层调度板块相同：Laravel **API Resource** + 分页 `data/links/meta`；聚合接口返回裸 JSON。

| 接口 | 响应形态 |
|------|----------|
| `qc-standards/summary` | 对齐 `qc-standards.json`（无外层 code） |
| `sla-records` index | 对齐 `qc-sla.json`：`updatedAt`, `rules`, `records[]` |
| `qc-issues-report` | 统计 JSON，见 §5.1 |
| `qc-issues` CRUD | Resource 包装 |

**桥接**：开发环境 `fetch('/api/qc-standards.json')` → `GET /v1/qc-standards/summary`；`fetch('/api/qc-sla.json')` → `GET /v1/sla-records`（前端需展平 `records.data` 若存在）。

## 3. 数据模型

### 3.1 质控标准 `qc_standards`

| 字段 | 说明 |
|------|------|
| version | 版本，如 2026-Q4 |
| standard_name | 标准名称 |
| category | 分类/达标要求描述（summary 映射为前端 `target`） |
| target_rate | 目标合规率 0~1 |
| sort | 排序 |
| is_active | 是否启用 |

### 3.2 质控整改单 `qc_issues`

| 字段 | 说明 |
|------|------|
| qc_code | 质控编号，唯一 |
| issue_title | 问题标题 |
| severity | SEVERITY_LOW / MEDIUM / HIGH |
| issue_source | 问题来源 |
| owner_user_id | 责任人 |
| current_stage | 当前环节 |
| qc_status | QC_OPEN / QC_RECTIFYING / QC_CLOSED |
| state_version | 乐观锁版本，从 1 起 |
| due_at | 整改期限 |
| related_type / related_id | 关联对象（如 QC_STANDARD） |
| supervise_target | 督查对象（报表按机构聚合） |
| check_method / check_item / check_result | 检查与结果 |
| discovered_at | 发现日期 |
| is_on_time_completed | 是否按期完成（销号时计算） |
| event_id | 可选，关联急救事件 |

### 3.3 环节时限 `sla_records`

| 字段 | 说明 |
|------|------|
| sla_code | 记录编号（Resource 输出为 `id`） |
| kind | 预警到床 / 出警到院 等 |
| rule_id | SLA-ALERT / SLA-DISPATCH |
| subject / owner | 对象与责任人 |
| role_view | doctor / director |
| started_at / arrived_at | 计时起止 |
| limit_minutes / used_minutes | 时限与已用 |
| overtime | 是否超时 |

**规则常量**（未落库，由 `SlaRecordController::RULES` 返回）与 mock `qc-sla.json` 的 `rules` 一致。

## 4. 接口清单 · 4.2 质控统计

### 4.1 GET `/api/v1/qc-issues-report` — 质控报表聚合

| 项目 | 内容 |
|------|------|
| 前端 | `/#/medical-quality/reports` API 面板 |
| 说明 | 级别分布、状态分布、机构维度统计 |

**响应字段**

| 字段 | 类型 | 说明 |
|------|------|------|
| updatedAt | string | ISO 8601 |
| total | int | 整改单总数 |
| by_severity | object | key=severity，value=count |
| by_status | object | key=qc_status，value=count |
| by_org | array | 每项见下表 |

**by_org[]**

| 字段 | 说明 |
|------|------|
| supervise_target | 督查对象名称 |
| total | 总数 |
| closed | 已销号数 |
| overdue | 超期未关闭数 |
| on_time_rate | 已关闭中按期完成比例 0~1，nullable |

**示例**

```json
{
  "updatedAt": "2026-10-13T20:00:00+08:00",
  "total": 12,
  "by_severity": { "SEVERITY_HIGH": 2, "SEVERITY_MEDIUM": 7, "SEVERITY_LOW": 3 },
  "by_status": { "QC_OPEN": 4, "QC_RECTIFYING": 3, "QC_CLOSED": 5 },
  "by_org": [
    {
      "supervise_target": "威远县人民医院·急诊科",
      "total": 5,
      "closed": 2,
      "overdue": 1,
      "on_time_rate": 0.5
    }
  ]
}
```

---

### 4.2 GET `/api/v1/qc-issues-export` — 整改台账 CSV 导出

| 项目 | 内容 |
|------|------|
| 响应 | `text/csv` 流式下载 |
| 列 | 质控编号、问题标题、严重程度、督查对象、质控状态、整改期限、是否按期完成、检查结果、发现日期等 |

前端可直接 `<a href="/backend-api/v1/qc-issues-export">`（开发代理）或生产网关同源路径。

---

### 4.3 GET `/api/v1/qc-standards/summary` — 标准汇总（Mock 契约）

对齐 `qc-standards.json`，供 `QcStandards.vue` 与 `fetch('/api/qc-standards.json')`。

**响应**

| 字段 | 说明 |
|------|------|
| version | 当前启用标准的最新 version |
| updatedAt | 服务器时间 |
| standards[] | id, name, target, samplePeriod, complianceRate |
| recentEvents[] | at, standardId, ok, note |

**complianceRate 计算**：关联 `qc_issues` 中 `related_type=QC_STANDARD` 且 `QC_CLOSED` 的按期完成率；无样本时回退 `target_rate`。

**recentEvents**：最近 10 条 `qc_issues`，`ok` 由 `check_result=达标` 或 `is_on_time_completed=true` 推导。

---

### 4.4 GET `/api/v1/qc-standards` — 标准 CRUD 列表

**Query**：`version`, `is_active`, `page`, `per_page`（默认 50）。

**QcStandardResource**：`id`, `version`, `standard_name`, `category`, `target_rate`, `sort`, `is_active`, `created_at`, `updated_at`。

---

### 4.5 POST `/api/v1/qc-standards` — 新增标准

Body（StoreQcStandardRequest）：`version`, `standard_name`, `category`, `target_rate`, `sort`, `is_active` 等。成功 **201**。

---

### 4.6 GET/PUT/DELETE `/api/v1/qc-standards/{id}`

标准详情、更新（UpdateQcStandardRequest）、物理删除 **204**。

---

### 4.7 GET `/api/v1/qc-issues` — 整改台账列表

**Query**

| 参数 | 说明 |
|------|------|
| qc_status | QC_OPEN / QC_RECTIFYING / QC_CLOSED |
| severity | SEVERITY_* |
| owner_user_id | 责任人 |
| event_id | 关联急救事件 |
| overdue | boolean，true=未关闭且 due_at&lt;now |
| keyword | 编号/标题/督查对象模糊 |
| page / per_page | 默认 15 |

**QcIssueResource 字段**：`id`, `qc_code`, `issue_title`, `severity`, `issue_source`, `owner_user_id`, `owner_name`, `current_stage`, `qc_status`, `state_version`, `due_at`, `related_type`, `related_id`, `supervise_target`, `check_*`, `discovered_at`, `is_on_time_completed`, `event_id`, `created_at`, `updated_at`。

---

### 4.8 POST `/api/v1/qc-issues` — 登记质控问题

**Body（必填/常用）**

| 字段 | 规则 |
|------|------|
| issue_title | required, max:200 |
| severity | 可选 SEVERITY_LOW/MEDIUM/HIGH |
| owner_user_id | 可选 exists:users |
| due_at | 可选 date |
| qc_status | 可选，默认 QC_OPEN |
| related_type / related_id | 关联标准或事件 |
| supervise_target | 督查对象 |
| event_id | 关联急救事件 |

成功 **201**。`qc_code` 由模型生成。

---

### 4.9 GET `/api/v1/qc-issues/{id}` — 整改单详情

加载 `owner`, `event`。

---

### 4.10 PUT/PATCH `/api/v1/qc-issues/{id}` — 更新整改单

**Body 必须含** `state_version`（当前版本）。服务端写入 `state_version+1`；若库中版本不一致返回 **409**。

---

### 4.11 POST `/api/v1/qc-issues/{id}/close` — 销号

**Body**

| 字段 | 必填 | 说明 |
|------|------|------|
| check_result | 是 | 检查结果描述 |
| state_version | 是 | 乐观锁 |

**业务**：非 QC_CLOSED → QC_CLOSED；`is_on_time_completed` = `due_at` 为空或 now≤due_at；版本冲突 **409**。

---

### 4.12 DELETE `/api/v1/qc-issues/{id}` — 删除

HTTP **204**，软删除。

## 5. 接口清单 · 4.1 智能监控

### 5.1 GET `/api/v1/sla-records` — 环节时限（规则 + 台账）

**Query**

| 参数 | 说明 |
|------|------|
| rule_id | SLA-ALERT / SLA-DISPATCH |
| role_view | doctor / director |
| overtime | boolean，是否超时 |
| page | 分页（index 当前实现为全量 get 后嵌入 records；生产可改为 paginate） |

**响应（契约）**

```json
{
  "updatedAt": "2026-10-13T20:00:00+08:00",
  "rules": [
    {
      "id": "SLA-ALERT",
      "name": "预警后到床",
      "limitMinutes": 10,
      "audience": "当班医生 · 看自己负责患者是否超时"
    },
    {
      "id": "SLA-DISPATCH",
      "name": "出警后到院",
      "limitMinutes": 30,
      "audience": "护士长 / 院长 · 看出车环节超时"
    }
  ],
  "records": [
    {
      "id": "SLA-20261012-01",
      "kind": "预警到床",
      "ruleId": "SLA-ALERT",
      "subject": "演示患者01 · ICU 1床",
      "owner": "张医生",
      "roleView": "doctor",
      "startedAt": "2026-10-12T14:08:00+08:00",
      "arrivedAt": "2026-10-12T14:15:00+08:00",
      "limitMinutes": 10,
      "usedMinutes": 7,
      "overtime": false
    }
  ]
}
```

**与前端 enhance 关系**：`qc-sla-enhance.js` 合并 scenario 预警/出车演示行与上述 `records`；接后端后 mock 路径经 bridge 自动替换。

---

### 5.2 POST `/api/v1/sla-records` — 登记时限记录

| 字段 | 必填 | 说明 |
|------|------|------|
| kind | 是 | 时限类型 |
| rule_id | 是 | 规则 ID |
| subject | 是 | 对象描述 |
| started_at | 是 | 开始时间 |
| limit_minutes | 是 | ≥1 |
| owner / role_view | 否 | |
| arrived_at | 否 | 到达后重算 used_minutes、overtime |

服务端自动计算 `used_minutes`、`overtime`（未到达则按当前时间计时）。

---

### 5.3 GET/PUT/DELETE `/api/v1/sla-records/{id}`

`{id}` 为表主键；Resource 对外 `id` 字段为 `sla_code`。更新时若补录 `arrived_at` 会重算超时。

---

### 5.4 智能监控扩展（跨域只读）

## 6. 接口清单 · 4.3 质控提醒

### 6.1 超期整改提醒

**GET** `/api/v1/qc-issues?overdue=true`

返回未关闭且 `due_at < now()` 的整改单，供看板「超期预警」列或消息推送源。

### 6.2 环节超时提醒

**GET** `/api/v1/sla-records?overtime=true`

或在前端对 `records` 中 `overtime===true` 高亮（`qc-sla-enhance.js` 已支持 `over` 样式）。

### 6.3 标准抽检异常

**GET** `/api/v1/qc-standards/summary` → `recentEvents[]` 中 `ok: false` 条目，映射 4.3「质控提醒」轻量通知。

### 6.4 推送通道（未实现）

WebSocket / 企业微信 / 短信下发需独立消息服务；本后端仅提供查询接口。
