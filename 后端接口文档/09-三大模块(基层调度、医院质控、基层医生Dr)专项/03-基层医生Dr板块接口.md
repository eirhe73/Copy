## 2. 5.1 视频展示（前端契约，非 REST）

### 2.1 能力说明

| 项 | 内容 |
|----|------|
| 页面 | `/#/dr`，class `dr-page` |
| 增强脚本 | `public/assets/dr-video-enhance.js` |
| 行为 | 将播放列表中带 `data-topic` 的条目替换为 Bilibili `<iframe>`，隐藏原 `<video src="/media/...">` |
| 样式 | `theme-light.css`：`.dr-player--bili`、`.dr-player-panel--bili` |

### 2.2 内置 topic → BV 号映射（可扩展）

| data-topic | Bilibili BV | 说明 |
|------------|-------------|------|
| cpr | BV1Sp4y1z7wN | CPR 相关 |
| earthquake | BV1sA411J7WY | 地震创伤 |
| flu | BV1BmCLBmE3D | 流感/呼吸道 |

未配置 topic 的条目仍指向 `/media/*.mp4`（仓库内文件可能缺失，需自备或继续走 Bilibili 映射）。

### 2.3 生产接入建议（接口化可选）

若需运营可配视频，可增加配置接口（**规划，未实现**）：

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/dr/playlists` | 返回 `{ items: [{ id, title, topic, provider, embedUrl, coverUrl }] }` |
| PUT | `/api/v1/dr/playlists/{id}` | 管理端维护 |

当前**不强制**后端；静态 JS 映射即可满足演示与内网联调。

## 3. 数据模型

### 3.1 医生（users 表，identity_type=DOCTOR）

| 字段 | 说明 |
|------|------|
| id | 主键 |
| org_id | 所属基层机构 |
| real_name | 姓名 |
| username | 登录账号，唯一 |
| password_hash | 密码哈希（接口写入时用 `password` 字段） |
| phone / email | 联系方式 |
| identity_type | 固定 `DOCTOR` |
| home_route | 登录后默认路由，如 `/#/dr` |
| user_status | USER_ACTIVE / USER_DISABLED |
| last_login_at | 最后登录 |

### 3.2 诊疗记录 `clinical_records`

与基层调度 3.4 共用，见《01-基层调度板块接口.md》§3.4、§6。

## 4. 接口清单 · 医生管理

### 4.1 GET `/api/v1/doctors` — 基层医生列表

**Query**

| 参数 | 说明 |
|------|------|
| org_id | 按机构 |
| user_status | USER_ACTIVE / USER_DISABLED |
| keyword | 姓名 / 账号 / 手机模糊 |
| page / per_page | 默认 15 |

**DoctorResource**

| 字段 | 说明 |
|------|------|
| id | users.id |
| real_name / username | 姓名 / 账号 |
| org_id | 机构 ID |
| org | OrganizationResource（whenLoaded） |
| phone / email | |
| identity_type | DOCTOR |
| home_route | |
| user_status | |
| last_login_at / created_at / updated_at | ISO 8601 |

**注意**：响应不含 `password_hash`。

---

### 4.2 POST `/api/v1/doctors` — 录入医生

**Body**

| 字段 | 必填 | 规则 |
|------|------|------|
| real_name | 是 | max:100 |
| username | 是 | unique:users |
| password | 是 | min:6 |
| org_id | 否 | exists:organizations |
| phone / email | 否 | |
| home_route | 否 | max:200 |
| user_status | 否 | USER_ACTIVE / USER_DISABLED |

服务端：`identity_type=DOCTOR`，`password` → `Hash::make` 存 `password_hash`。成功 **201**。

---

### 4.3 GET `/api/v1/doctors/{id}` — 医生详情

路径参数为 `users.id`；非 DOCTOR 身份返回 **404**。

---

### 4.4 PUT/PATCH `/api/v1/doctors/{id}` — 更新医生

**Body**：同创建，字段均为 sometimes；若传 `password` 则重新哈希。

---

### 4.5 DELETE `/api/v1/doctors/{id}` — 删除医生

HTTP **204**，软删除。非 DOCTOR **404**。

---

## 5. 接口清单 · 诊疗记录（Dr 页数据面板）

与 **3.4 基层远程监护** 共用 REST，Dr 页侧重「近期记录列表」展示。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/clinical-records` | 按 `doctor_user_id`、`org_id` 筛选 |
| POST | `/api/v1/clinical-records` | 基层医生录入接诊 |
| GET | `/api/v1/clinical-records/{id}` | 详情 |
| PUT/PATCH | `/api/v1/clinical-records/{id}` | 更新 |
| DELETE | `/api/v1/clinical-records/{id}` | 删除 |

**POST Body 摘要**：`patient_id`, `doctor_user_id`, `visit_at` 必填；`record_type` 默认 OUTPATIENT；`chief_complaint`, `diagnosis`, `treatment` 等可选。

详见《01-基层调度板块接口.md》§6。

## 6. 响应与错误

| 场景 | HTTP |  body |
|------|------|------|
| 校验失败 | 422 | `{ message, errors }` |
| 非医生资源 | 404 | Laravel 默认 |
| 列表分页 | 200 | `{ data[], links, meta }` |

认证：当前未强制 Sanctum；生产应对 `POST/PUT/DELETE` 限权（仅本机构 `org_id`）。

## 7. 前端对接

| 文件 | 作用 |
|------|------|
| `index.html` | 加载 `backend-api-bridge.js`、`plate-three-backend-enhance.js`、`dr-video-enhance.js` |
| `plate-three-backend-enhance.js` | `/dr` 路由下并行请求 `doctors`、`clinical-records` |
| `backend-api-bridge.js` | 不映射 Dr 专用 mock；面板直连 `/backend-api/v1` |

**联调步骤**

1. `php artisan serve` + `npm run dev`  
2. 打开 `http://127.0.0.1:5173/#/dr`  
3. 确认 API 面板「后端已连接」及医生/记录列表
