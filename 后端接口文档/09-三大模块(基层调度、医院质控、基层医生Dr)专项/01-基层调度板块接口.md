## 2. 响应与分页约定（Laravel 实装）

当前 v1 接口**未**统一包裹 `{ code, message, data }`，而是：

| 类型 | 结构 |
|------|------|
| 单条 Resource | `{ "data": { ...字段 } }` |
| 分页列表 | `{ "data": [ ... ], "links": { first, last, prev, next }, "meta": { current_page, per_page, total, ... } }` |
| 聚合/契约接口 | 裸 JSON（如 `dispatch-live`、`qc-standards/summary` 形态） |
| 校验失败 | HTTP 422，`{ "message": "...", "errors": { "field": ["..."] } }` |
| 乐观锁冲突 | HTTP 409，`{ "message": "..." }` |
| 删除成功 | HTTP 204 No Content |

**Query 分页参数**：`page`（默认 1）、`per_page`（默认 15 或 50，见各接口说明）。

时间字段：ISO 8601 字符串（Resource 层 `toIso8601String()`）。

认证：路由组当前**未**挂载 `auth:sanctum`；生产环境建议对写操作启用 Token。

## 3. 数据模型

### 3.1 机构表 `organizations`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键 |
| org_code | string(50) | 机构编码，唯一 |
| org_name | string(200) | 机构名称 |
| org_type | string(50) | 县医院 / 乡镇卫生院 / 急救中心等 |
| county_name | string(100) | 所属县域 |
| address | string(500) | 地址 |
| lng / lat | decimal(10,6) | WGS84 坐标 |
| contact_phone | string(50) | 联系电话 |
| is_deleted / deleted_at | bool / datetime | 软删除 |

### 3.2 科室表 `departments`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键 |
| org_id | bigint | 所属机构 |
| dept_code | string(50) | 科室编码（同机构唯一） |
| dept_name | string(100) | 科室名称 |

### 3.3 转诊单表 `transfers`

| 字段 | 类型 | 说明 |
|------|------|------|
| transfer_code | string(50) | 转诊单号，唯一（创建时由模型/Observer 生成） |
| event_id | bigint | 可选，关联急救事件 |
| patient_id | bigint | 可选，关联患者 |
| from_org_id / to_org_id | bigint | 转出 / 转入机构 |
| urgency_level | string | `URGENCY_LOW` / `URGENCY_MEDIUM` / `URGENCY_HIGH` |
| transfer_reason | text | 转诊原因（必填） |
| diagnosis | string(200) | 诊断 |
| trigger_source | string(50) | 触发来源 |
| transfer_status | string | 见 §6.1 |
| confirm_status | string | 见 §6.2 |
| confirmed_at / confirmed_by_user_id | datetime / bigint | 确认信息 |
| reject_reason | text | 驳回原因 |
| review_note | string(500) | 审核备注 |
| vehicle_id / driver_name / eta | | 转运安排 |
| latest_vitals | json | **远程监护**：最新生命体征快照 |
| resource_prep | json | 接收方资源准备 |
| handover_status | string(30) | 交接状态 |
| initiator_user_id | bigint | 发起人（users.id） |

| visit_at | datetime | 就诊时间 |

### 4.1 GET `/api/v1/organizations` — 机构列表

## 5. 接口清单 · 3.2 医院转诊

### 5.1 GET `/api/v1/transfers` — 转诊单列表

**Query**

| 参数 | 说明 |
|------|------|
| transfer_status | 转诊状态，见 §6.1 |
| confirm_status | 确认状态，见 §6.2 |
| urgency_level | 紧急程度枚举 |
| from_org_id / to_org_id | 机构筛选 |
| event_id | 关联急救事件 |
| keyword | 转诊单号模糊 |
| page / per_page | 默认 per_page=15 |

**TransferResource 主要字段**

| 字段 | 说明 |
|------|------|
| id | 主键 |
| transfer_code | 转诊单号 |
| event_id / patient_id | 关联 ID |
| urgency_level | 紧急度 |
| transfer_reason / diagnosis | 原因 / 诊断 |
| trigger_source | 触发来源 |
| transfer_status / confirm_status | 状态 |
| confirmed_at / reject_reason / review_note | 确认与审核 |
| driver_name / eta | 转运 |
| latest_vitals | object，体征 JSON（监护） |
| resource_prep | object，资源准备 |
| handover_status | 交接 |
| from_org / to_org | 嵌套 OrganizationResource |
| patient | 嵌套 PatientResource（若加载） |
| vehicle | 嵌套 VehicleResource（若加载） |
| created_at / updated_at | 时间 |

---

### 5.2 POST `/api/v1/transfers` — 发起转诊

**Body（JSON）**

| 字段 | 必填 | 规则 |
|------|------|------|
| from_org_id | 是 | exists:organizations |
| transfer_reason | 是 | string |
| initiator_user_id | 是 | exists:users |
| to_org_id | 否 | exists:organizations |
| event_id / patient_id | 否 | 关联急救事件/患者 |
| urgency_level | 否 | URGENCY_LOW / MEDIUM / HIGH |
| diagnosis | 否 | max:200 |
| trigger_source | 否 | max:50 |
| vehicle_id | 否 | exists:vehicles |
| driver_name / eta | 否 | |
| latest_vitals / resource_prep | 否 | array（JSON） |

**成功**：HTTP **201**，body `{ "data": TransferResource }`。  
**默认状态**：`transfer_status=TRANSFER_PENDING`，`confirm_status=CONFIRM_PENDING`（模型默认值）。

---

### 5.3 GET `/api/v1/transfers/{id}` — 转诊详情

加载关联：`fromOrg`, `toOrg`, `patient`, `vehicle`, `event`。

---

### 5.4 PUT/PATCH `/api/v1/transfers/{id}` — 更新转诊

Body 字段同创建，均为 `sometimes` 可选。用于更新车辆、ETA、**latest_vitals**、resource_prep、handover_status 等。

---

### 5.5 POST `/api/v1/transfers/{id}/confirm` — 接收方确认

**Body**

| 字段 | 必填 | 说明 |
|------|------|------|
| confirmed_by_user_id | 否 | 确认人 users.id |
| review_note | 否 | max:500 |

**业务效果**：`confirm_status=CONFIRM_CONFIRMED`，`transfer_status=TRANSFER_CONFIRMED`，`confirmed_at=now()`。

---

### 5.6 POST `/api/v1/transfers/{id}/reject` — 接收方驳回

**Body**

| 字段 | 必填 | 说明 |
|------|------|------|
| reject_reason | 是 | 驳回原因 |
| confirmed_by_user_id | 否 | 操作人 |

**业务效果**：`confirm_status=CONFIRM_REJECTED`，`transfer_status=TRANSFER_REJECTED`。

---

### 5.7 DELETE `/api/v1/transfers/{id}` — 删除转诊单

HTTP **204**。模型软删除（`is_deleted` / `deleted_at`）。

### 6.1 GET `/api/v1/clinical-records` — 诊疗/监护记录列表

用于基层机构侧**远程随访、监护摘要**展示（非实时视频流）。

**Query**

| 参数 | 说明 |
|------|------|
| patient_id | 按患者 |
| doctor_user_id | 按医生 |
| org_id | 按机构 |
| record_type | OUTPATIENT / EMERGENCY / FOLLOW_UP |
| visit_from / visit_to | 就诊时间范围 |
| keyword | 记录号 / 主诉 / 诊断模糊 |
| page / per_page | 默认 15 |

**ClinicalRecordResource**：`id`, `record_code`, `patient_id`, `patient`, `doctor_user_id`, `doctor_name`, `org_id`, `org`, `record_type`, `chief_complaint`, `present_history`, `diagnosis`, `treatment`, `visit_at`, `created_at`, `updated_at`。

---

### 6.2 POST `/api/v1/clinical-records` — 新增记录

| 字段 | 必填 | 说明 |
|------|------|------|
| patient_id | 是 | |
| doctor_user_id | 是 | |
| visit_at | 是 | date |
| org_id | 否 | |
| record_type | 否 | 默认 OUTPATIENT |
| chief_complaint / present_history / diagnosis / treatment | 否 | |

成功 HTTP **201**。

---

### 6.3 GET/PUT/DELETE `/api/v1/clinical-records/{id}`

实时视频流（RTSP/HLS/GB28181）**不在本后端**；前端 `/#/critical` 视频监控仍为演示占位。
