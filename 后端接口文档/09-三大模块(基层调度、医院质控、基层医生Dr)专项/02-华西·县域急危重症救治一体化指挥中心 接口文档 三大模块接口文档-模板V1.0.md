## 1. 通用约定

> **V1.0 说明：以下约定已对照本项目既有文档体系（`00-总览/README.md`）与前端代码逐一核实。后端（`backend/` Laravel 10）当前为空壳脚手架，三大模块接口均待开发；前端侧院前调度页面已实现并依赖 Mock 数据。**

### 1.1 Base URL

- 基础路径统一为 `/api/v1`
- 本地开发与线上 Host 按部署域名确定【待确认：当前后端未定义部署地址】

### 1.2 鉴权方式

后端鉴权框架统一为 **Laravel Sanctum**。

默认请求头约定：

- `Authorization: Bearer <token>`

说明：

- 除健康检查 `GET /api/v1/health` 与登录 `POST /api/v1/auth/login` 外，其余接口均需要登录（登录接口见 `08-系统/01-认证接口.md`，不在本文档范围）。
- 数据权限维度预留 `roleView`（`doctor` / `director`），用于质控/SLA 数据集权限，见 §1.7.11。

### 1.3 统一响应格式

所有接口统一返回：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

字段说明：

- `code`：业务状态码，成功为 `200`，非 200 表示业务异常
- `message`：业务提示信息
- `data`：返回数据，可能为对象、数组或 `null`

> 与模板差异：本项目现状无 `timestamp` / `traceId` 字段；如需链路追踪能力需后端补充（见 §7 改写说明）。
> PHP 输出使用 `json_encode($response, JSON_UNESCAPED_UNICODE)`，确保中文不被转义。

### 1.4 分页响应格式

分页接口的 `data` 统一为：

```json
{
  "list": [],
  "total": 100
}
```

> 当前演示前端所有列表均为一次全量加载 + 本地轮询，无真实分页 UI；分页参数为可选兼容项。部分聚合接口（如整改台账）在 `data` 顶层额外携带 `updatedAt`、`summary` 等汇总字段。

### 1.5 时间与排序约定

- 时间字段统一使用 ISO 8601（含时区），例如：`2026-10-12T14:08:00+08:00`
- 数据库存储为 `DATETIME`（`YYYY-MM-DD HH:MM:SS`），接口返回时转换
- 分页参数：
  - `pageNum`：页码，从 `1` 开始
  - `pageSize`：每页条数，默认 `10`，最大 `100`
- 现有接口未定义通用 `sort` 排序参数，列表排序由后端固定（如按时间倒序）【待确认：是否需要统一排序参数】

### 1.6 请求参数示例写法

本文档中的"请求参数示例"统一采用如下结构：

- `path`：路径参数
- `query`：查询参数
- `body`：JSON 请求体
- `formData`：`multipart/form-data` 表单字段

无对应参数时，明确写为 `null` 或空对象 `{}`。

### 1.7 通用枚举约定

#### 1.7.1 事件/车辆状态 `status`

| 存储值（接口返回） | 显示文本 | 场景 |
| --- | --- | --- |
| `STANDBY` | 待命 | 车辆空闲 |
| `DISPATCHING` | 出警中 | 车辆/事件 |
| `ON_SCENE` | 现场处置 | 车辆/事件 |
| `RETURNING` | 返院途中 | 车辆/事件 |

> 库内以 TINYINT（0~3）存储，接口返回英文码 + `statusLabel` 中文文案，前端做映射。

#### 1.7.2 事件等级 `level`

| 存储值 | 显示文本 |
| --- | --- |
| `CRITICAL` | 重症 |
| `ACUTE` | 急症 |
| `GENERAL` | 一般 |

#### 1.7.3 性别 `gender`

| 存储值 | 显示文本 |
| --- | --- |
| `MALE` | 男 |
| `FEMALE` | 女 |

#### 1.7.4 转诊方向 `direction`

| 存储值 | 显示文本 | 说明 |
| --- | --- | --- |
| `UP` | 上转 | 下级 → 上级（含华西） |
| `DOWN` | 下转 | 上级 → 下级 |

#### 1.7.5 转诊状态 `status`

| 存储值 | 显示文本 |
| --- | --- |
| `REQUESTED` | 待接收 |
| `ACCEPTED` | 已接收 |
| `IN_TRANSIT` | 转运中 |
| `ARRIVED` | 到院 |
| `COMPLETED` | 已完成 |
| `REJECTED` | 已拒绝 |

> 状态流转：`REQUESTED → ACCEPTED → IN_TRANSIT → ARRIVED → COMPLETED`；`REQUESTED → REJECTED` 为终态。

#### 1.7.6 华西绿色通道类型 `channelType`

| 存储值 | 显示文本 |
| --- | --- |

#### 1.7.7 整改问题来源 `source`

| 存储值 | 显示文本 |
| --- | --- |

| `pathwayTimeout` | 绿色通道超时 |
| `inspection` | 质控检查 |
| `complaint` | 投诉反馈 |
| `manual` | 人工登记 |

#### 1.7.8 整改级别 `level`

| 存储值 | 显示文本 |
| --- | --- |
| `1` | 严重 |
| `2` | 一般 |
| `3` | 轻微 |

#### 1.7.9 整改状态 `status`

| 存储值 | 显示文本 |
| --- | --- |
| `pending` | 待整改 |
| `rectifying` | 整改中 |
| `reviewing` | 待复评 |
| `closed` | 已销号 |

#### 1.7.10 销号流转动作 `action`

| 存储值 | 显示文本 | 流转 |
| --- | --- | --- |
| `start` | 开始整改 | pending → rectifying |
| `submit` | 提交复评 | rectifying → reviewing |
| `approve` | 复评通过并销号 | reviewing → closed |
| `reject` | 退回整改 | reviewing → rectifying |

#### 1.7.11 数据权限角色 `roleView`

| 存储值 | 说明 |
| --- | --- |
| `doctor` | 当班医生：仅看本人负责的 SLA/整改记录 |
| `director` | 管理者（护士长/院长/质控）：查看全院 |

#### 1.7.12 基层反馈类型与状态

反馈类型 `category`：`FEEDBACK`（基层反馈）/ `ISSUE`（问题上报）。

反馈优先级 `priority`：`0` 普通 / `1` 紧急。

反馈状态 `status`：`PENDING`（待处理）→ `REPLIED`（已回复）→ `RESOLVED`（已办结）。

#### 1.7.13 协作消息类型 `kind`

| 存储值 | 显示文本 | 说明 |
| --- | --- | --- |
| `TEXT` | 文字 | `content` 为正文 |
| `VOICE` | 语音 | `mediaUrl` 为音频，携 `durationSec` |
| `IMAGE` | 图片 | `mediaUrl` 为图片地址 |
| `FILE` | 文件 | `mediaUrl` 为文件地址 |

#### 2.1.4 `POST /api/v1/dispatch/events`

- **接口中文名**：创建急救事件（接警建档）
- **请求体**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| task120Id | string | 是 | 120 任务号，如 `120-WY-88450` |
| level | string | 否 | 事件等级，缺省 `GENERAL` |
| chiefComplaint | string | 是 | 主诉 |
| pickupAddress | string | 是 | 接车地址 |
| destination | string | 否 | 目标医院 |
| startedAt | string | 否 | 出警时间（ISO 8601） |

- **请求参数示例**

```json
{
  "path": {},
  "query": {},
  "body": {
    "task120Id": "120-WY-88450",
    "level": "CRITICAL",
    "chiefComplaint": "胸痛、意识模糊",
    "pickupAddress": "威远县连界镇",
    "destination": "威远县人民医院",
    "startedAt": "2026-10-12T14:05:00+08:00"
  }
}
```

- **响应 `data`**

```json
{
  "eventId": "EVT-20261012-04",
  "task120Id": "120-WY-88450",
  "status": "DISPATCHING"
}
```

- **业务规则**：前端为占位页（字段为规范设计）；`task120Id` 唯一，重复创建返回 400
- **错误码**

| code | message | 条件 |
| --- | --- | --- |
| 200 | success | 成功 |
| 400 | 参数校验失败 | chiefComplaint 为空 / task120Id 已存在 |
| 401 | 未认证或 Token 失效 | 未登录 |

#### 2.1.5 `PUT /api/v1/dispatch/events/{eventId}`

- **接口中文名**：更新事件状态
- **Path 参数**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| eventId | string | 是 | 事件编号 |

- **请求体**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| status | string | 是 | 目标状态：`DISPATCHING/ON_SCENE/RETURNING` |
| updatedAt | string | 否 | 操作时间（ISO 8601） |

- **请求参数示例**

```json
{
  "path": { "eventId": "EVT-20261012-01" },
  "query": {},
  "body": {
    "status": "ON_SCENE"
  }
}
```

- **响应 `data`**

```json
{
  "eventId": "EVT-20261012-01",
  "status": "ON_SCENE",
  "statusLabel": "现场处置"
}
```

- **业务规则**：状态流转同步更新车辆状态；非法流转（如 `RETURNING → DISPATCHING` 回退）返回 400
- **错误码**

| code | message | 条件 |
| --- | --- | --- |
| 200 | success | 成功 |
| 400 | 非法状态流转 | 状态机不允许的跳跃 |
| 401 | 未认证或 Token 失效 | 未登录 |
| 404 | 事件不存在 | eventId 无效 |
