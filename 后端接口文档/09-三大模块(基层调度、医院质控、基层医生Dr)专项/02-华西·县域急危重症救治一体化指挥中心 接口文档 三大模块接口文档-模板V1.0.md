## 1. 通用约定

> **V1.0 说明：以下约定已对照本项目既有文档体系（`00-总览/README.md`）与前端代码逐一核实。后端（`backend/` Laravel 10）当前为空壳脚手架，三大模块接口均待开发；前端侧院前调度页面已实现并依赖 Mock 数据。**

### 1.1 Base URL

- 基础路径统一为 `/api/v1`
- 本地开发与线上 Host 按部署域名确定【待确认：当前后端未定义部署地址】

### 1.2 鉴权方式

后端鉴权框架为 **JWT**（tymon/jwt-auth，guard `api`，业务路由统一经 `auth:api` 中间件校验）。

默认请求头约定：

- `Authorization: Bearer <token>`

说明：

- `POST /api/v1/auth/login`：账号 + 密码 → 返回 `token` 与 `tokenType: "Bearer"`，并记录最近登录时间/IP；`POST /api/v1/auth/logout`、`GET /api/v1/auth/me` 需登录后调用。除健康检查与登录外，其余接口均需要登录。
- 数据权限字段已落库 `users.role_view`（`doctor` / `director`，默认 `doctor`），用于质控/SLA 数据集权限，见 §1.7.11。

### 1.3 统一响应格式

所有接口统一返回：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

字段说明：

- `code`：业务状态码，成功为 `200`，非 200 表示业务异常
- `message`：业务提示信息
- `data`：返回数据，可能为对象、数组或 `null`

> 与模板差异：本项目现状无 `timestamp` / `traceId` 字段；如需链路追踪能力需后端补充（见 §7 改写说明）。
> PHP 输出使用 `json_encode($response, JSON_UNESCAPED_UNICODE)`，确保中文不被转义。

### 1.4 分页响应格式

分页接口的 `data` 统一为：

```json
{
  "list": [],
  "total": 100
}
```

> 当前演示前端所有列表均为一次全量加载 + 本地轮询，无真实分页 UI；分页参数为可选兼容项。部分聚合接口（如整改台账）在 `data` 顶层额外携带 `updatedAt`、`summary` 等汇总字段。

### 1.5 时间与排序约定

- 时间字段统一使用 ISO 8601（含时区），例如：`2026-10-12T14:08:00+08:00`
- 数据库存储为 `DATETIME`（`YYYY-MM-DD HH:MM:SS`），接口返回时转换
- 分页参数：
  - `pageNum`：页码，从 `1` 开始
  - `pageSize`：每页条数，默认 `10`，最大 `100`
- 现有接口未定义通用 `sort` 排序参数，列表排序由后端固定（如按时间倒序）【待确认：是否需要统一排序参数】

### 1.6 请求参数示例写法

本文档中的"请求参数示例"统一采用如下结构：

- `path`：路径参数
- `query`：查询参数
- `body`：JSON 请求体
- `formData`：`multipart/form-data` 表单字段

无对应参数时，明确写为 `null` 或空对象 `{}`。

- **接口中文名**：获取急救事件列表
- **查询参数**

| 参数 | 类型 | 必填 | 说明 |

```json
{

      "task120Id": "120-WY-88421",
      "level": "CRITICAL",
      "levelLabel": "重症",
      "chiefComplaint": "胸痛、意识模糊",
      "pickupAddress": "威远县连界镇",
      "destination": "威远县人民医院",
      "vehicleId": "AMB-1",
      "vehiclePlate": "演示001",
      "status": "DISPATCHING",
      "statusLabel": "出警中",
      "startedAt": "2026-10-12T14:05:00+08:00",
      "etaHospitalMinutes": 8,
      "etaPatientMinutes": 4,
      "scorePlan": "胸痛绿色通道 · NEWS 关注",
      "treatPlan": "吸氧、心电监护、准备阿司匹林，联系心内科会诊。"
    }
  ]
}
```

- **前端调用时机**：`#live`、`#events` 页加载时；`#live` 10s 轮询
- **代码逻辑**：
  1. 鉴权：JWT（guard `api`），除健康检查与登录外均需 Token（§1.2）。
  2. 查询 `emergency_event` 表（05 模块 1 §1.1）：`status` 参数逗号分隔 → `WHERE status IN (...)`（英文码，§1.7.1）；"进行中"= `DISPATCHING/ON_SCENE/RETURNING`。
  3. `activeCount` 为进行中事件的实时聚合计数（05 §5.3 派生不落库）；`updatedAt` 取服务器时间。
  4. 列表按 `started_at` 倒序 + `pageNum/pageSize` 分页（§1.4 `total/list` 外壳）。
  5. 字段组装（04 §6 DispatchEvent 映射）：`event_code→eventId`、`task_120_id→task120Id`、`level`（附 levelLabel）、`chief_complaint`、`pickup_address`、`destination`、`vehicle_id/vehicle_plate`、`status`（附 statusLabel）、`started_at`、`eta_hospital_minutes/eta_patient_minutes`、`score_plan`、`treat_plan`。
  6. 前端 10s 轮询（04 §5.1.1），建议后端加 3~5s 轻量缓存（05 §5.6）。
- **错误码**

| code | message | 条件 |
| --- | --- | --- |
| 200 | success | 成功 |
| 401 | 未认证或 Token 失效 | 未登录 |

#### 2.1.4 `POST /api/v1/dispatch/events`

- **接口中文名**：创建急救事件（接警建档）
- **请求体**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| task120Id | string | 是 | 120 任务号，如 `120-WY-88450` |
| level | string | 否 | 事件等级，缺省 `GENERAL` |
| chiefComplaint | string | 是 | 主诉 |
| pickupAddress | string | 是 | 接车地址 |
| destination | string | 否 | 目标医院 |
| startedAt | string | 否 | 出警时间（ISO 8601） |

- **请求参数示例**

```json
{
  "path": {},
  "query": {},
  "body": {
    "task120Id": "120-WY-88450",
    "level": "CRITICAL",
    "chiefComplaint": "胸痛、意识模糊",
    "pickupAddress": "威远县连界镇",
    "destination": "威远县人民医院",
    "startedAt": "2026-10-12T14:05:00+08:00"
  }
}
```

- **响应 `data`**

```json
{
  "eventId": "EVT-20261012-04",
  "task120Id": "120-WY-88450",
  "status": "DISPATCHING"
}
```

- **业务规则**：前端为占位页（字段为规范设计）；`task120Id` 唯一，重复创建返回 400
- **代码逻辑**：
  1. 校验必填：`task120Id`、`chiefComplaint`；`level` 缺省 `GENERAL`（§1.7.2）。
  2. 唯一性校验：`emergency_event.task_120_id` 唯一键（05），已存在 → 400。
  3. 生成事件编号 `event_code`（`EVT-日期-序号`），INSERT `emergency_event`：`task_120_id`、`level`、`chief_complaint`、`pickup_address`、`destination`、`started_at`（缺省当前时间）、`status=DISPATCHING`。
  4. 返回 `eventId`（event_code）、`task120Id`、`status`。
- **错误码**

| code | message | 条件 |
| --- | --- | --- |
| 200 | success | 成功 |
| 400 | 参数校验失败 | chiefComplaint 为空 / task120Id 已存在 |
| 401 | 未认证或 Token 失效 | 未登录 |

| --- | --- | --- |
| 200 | success | 成功 |
| 400 | 非法状态流转 | 状态机不允许的跳跃 |
| 401 | 未认证或 Token 失效 | 未登录 |
| 404 | 事件不存在 | eventId 无效 |

### 3.3 `POST /api/v1/qc/standards`

- **接口中文名**：新增质控标准
- **请求体**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| name | string | 是 | 标准名称 |
| target | string | 是 | 达标要求 |
| samplePeriod | string | 是 | 采样周期（月/季/年） |
| version | string | 是 | 标准版本，如 `2026-Q4-v1` |
| complianceRate | number | 否 | 合规率初值（0~1），缺省 `0` |

- **请求参数示例**

```json
{
  "path": {},
  "query": {},
  "body": {
    "name": "120出车响应",
    "target": "接警至出车 ≤ 3 分钟",
    "samplePeriod": "月",
    "version": "2026-Q4-v1",
    "complianceRate": 0
  }
}
```

- **响应 `data`**

```json
{ "id": "QC-ER-005", "version": "2026-Q4-v1" }
```

- **业务规则**：同 `id` 同 `version` 的标准唯一，冲突返回 409
- **代码逻辑**：
  1. 校验必填：`name`、`target`、`samplePeriod`、`version`；`complianceRate` 缺省 0。
  2. 版本归位：按 `version_code` 查 `qc_standard_version`，无则创建（05 §3.1 版本 → 标准项 1:N）。
  3. 唯一性：同版本下 `standard_code` 已存在 → 409（对应"同 id 同 version 唯一"）。
  4. INSERT `qc_standard`：`version_id`、`standard_code`（`QC-ER-00x` 生成）、`name`、`target`、`compliance_rate`、`enabled=1`；`samplePeriod` 05 未设列【待确认】。
  5. 返回 `id`（standard_code）、`version`。
- **错误码**

| code | message | 条件 |
| --- | --- | --- |
| 200 | success | 成功 |
| 400 | 参数校验失败 | name/target/version 为空 |
| 401 | 未认证或 Token 失效 | 未登录 |
| 409 | 标准已存在 | 同 id 同 version 唯一冲突 |

  4. 输出组装：`senderName` → `sys_user.real_name`（发送人关联）、`institutionName` → `organization.org_name`；`mediaUrl/durationSec` 随消息记录输出（语音连续播放列表依赖，04 §5.3）。
- **错误码**

| code | message | 条件 |
| --- | --- | --- |
| 200 | success | 成功 |
| 401 | 未认证或 Token 失效 | 未登录 |

### 4.5 `POST /api/v1/dr/messages`

- **接口中文名**：发送消息（协作沟通）
- **请求体**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| threadId | string | 否 | 协作链路（缺省新建链路并回传） |
| kind | string | 是 | 消息类型：`TEXT/VOICE/IMAGE/FILE` |
| content | string | 否 | 文字内容（kind=TEXT 必填） |
| mediaUrl | string | 否 | 媒体地址（VOICE/IMAGE/FILE 必填） |
| durationSec | number | 否 | 语音时长（秒），VOICE 建议携带 |
| receiverInstitutionId | string | 否 | 接收机构（指定协作对象） |

- **请求参数示例**

```json
{
  "path": {},
  "query": {},
  "body": {
    "threadId": "thread-wy-01",
    "kind": "TEXT",
    "content": "患者已开始转运，预计 30 分钟到院。",
    "receiverInstitutionId": "weiyuan"
  }
}
```

- **响应 `data`**

```json
{
  "messageId": "DR-MSG-1002",
  "threadId": "thread-wy-01",
  "kind": "TEXT",
  "createdAt": "2026-10-13T09:32:00+08:00"
}
```

- **业务规则**：同一协作对象收发消息共享 `threadId`，首条消息缺省新建链路；语音/图片/文件需先经文件上传接口落盘再携 `mediaUrl` 提交
- **代码逻辑**：
  1. **05 未覆盖**：协作消息表未建（同 §4.4）【建表待确认，见 §1.8-4】。
  2. 校验：`kind` 必填（§1.7.13 四类）；按 kind 校验内容——`TEXT → content` 必填、`VOICE/IMAGE/FILE → mediaUrl` 必填（先经文件上传落盘，校验地址可达），`VOICE` 建议携 `durationSec`。
  3. 链路归位：`threadId` 缺省则新建协作链路并回传；发送人 = 当前登录人（`sys_user`），`receiverInstitutionId` 指定接收机构。
  4. INSERT 消息记录（`threadId/kind/content/mediaUrl/durationSec/sender/receiverInstitutionId`，`isRead=false` 初始）；返回 `messageId/threadId/kind/createdAt`。
- **错误码**

| code | message | 条件 |
| --- | --- | --- |
| 200 | success | 成功 |
| 400 | 参数校验失败 | 文字为空 / 媒体地址为空 |
| 401 | 未认证或 Token 失效 | 未登录 |
