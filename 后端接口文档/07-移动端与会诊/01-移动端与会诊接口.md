
# 01 · 移动端与会诊接口

## 1. 页面/模块概述

| 项 | 内容 |
|----|------|
| 页面名称 | 现场工作台（`/#/coordination`）、手机重症接收（`/#/mobile-reception/:token`）、患者加入会诊（`/#/join/:token`）、移动入口（`/#/mobile`） |
| 核心功能 | 移动会诊待办、任务协同、手机端重症接收确认（机构选择 + 科室接收 + 到院准备） |
| 涉及实体 | 协同待办（coordination_todo）、协同任务（coordination_task）、手机重症接收单（mobile_reception）；下拉复用机构（organization）/ 科室（department） |
| 数据源 | `public/scenario.json` 顶层 `mobile`（`patients`/`journeys`/`dispatches`/`consultationRequests`/`alerts`/`clinicalNotes`/`events`）；路由模块见 `src/routes/meta.ts` |

对应路由（`routes/meta.ts`）与模块：

- `/coordination` 现场工作台：移动会诊待办、任务协同、Dr. 基层医声入口。
- `/mobile-reception/:token` 手机重症接收（standalone）：机构选择、科室接收、到院准备。
- `/join/:token` 患者加入会诊（standalone）：手机端入会、进度同步（会诊室接口见 [04-会诊协同/01-会诊协同接口](../../04-会诊协同/01-会诊协同接口.md)）。
- `/mobile`：重定向至 `/coordination`。

> 说明：本域所列页面均为 `PageScaffold` 占位脚手架，无独立 Mock JSON；字段依据 `scenario.mobile`（基层现场→县域重症接收的完整旅程数据）+ 模块描述还原，**接收/待办/任务相关字段为规范设计**，患者与院前字段对齐 `scenario.mobile.patients/journeys`。

## 2. 数据模型定义

> 机构 `organizations`、科室 `departments` 已在 [06-机构与配置/01-机构管理接口](../../06-机构与配置/01-机构管理接口.md) 定义，本域下拉接口复用，不重复建表。

### 2.1 协同待办表 `coordination_todos`

对应「现场工作台 · 移动会诊待办」。待办由基层上报、转诊申请、会诊申请、身份核实等业务事件驱动生成，面向现场医护（基层医生 / 随车医护）。

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |
|---------|-----------|------|------|------|
| 待办编号 | todo_id | String | 是 | 待办唯一键，继承 `messages.todos` 语义 |
| 归属人 | assignee_id | String | 是 | 待办责任人（对齐 `scenario.staff[].id`） |
| 标题 | title | String | 是 | 待办标题 |
| 提示 | hint | String | 否 | 待办提示文案 |
| 紧急度 | tone | String | 是 | danger/warn/default |
| 待办类型 | kind | String | 是 | consult_dispatch 待会诊 / transfer_confirm 待接收 / identity 待核实 / feedback 待确认 |
| 患者 | patient_id / patient_name | String | 否 | 关联患者 |
| 旅程 | journey_id | String | 否 | 关联 `scenario.mobile.journeys[].id` |
| 入会令牌 | token | String | 否 | 关联会诊/接收令牌（如 `xun-2026-0002`） |
| 来源机构/科室 | source_institution_id / source_department_id | String | 否 | 上报方 |
| 目标机构/科室 | target_institution_id / target_department_id | String | 否 | 接收方 |
| 优先级 | priority | String | 是 | P0 / P1 |
| 状态 | status | String | 是 | open/accepted/done |
| 生成时间 | at | DateTime | 是 | 待办生成时间 |
| 截止时间 | due_at | DateTime | 否 | 截止时间 |

```sql
CREATE TABLE `coordination_todos` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `todo_id` VARCHAR(64) NOT NULL COMMENT '待办编号',
  `assignee_id` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '待办责任人 staff.id',
  `title` VARCHAR(128) NOT NULL DEFAULT '' COMMENT '待办标题',
  `hint` VARCHAR(255) NOT NULL DEFAULT '' COMMENT '待办提示',
  `tone` VARCHAR(16) NOT NULL DEFAULT 'warn' COMMENT '紧急度：danger/warn/default',
  `kind` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '类型：consult_dispatch/transfer_confirm/identity/feedback',
  `patient_id` VARCHAR(64) NULL DEFAULT NULL COMMENT '关联患者编号',
  `patient_name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '关联患者姓名',
  `journey_id` VARCHAR(64) NULL DEFAULT NULL COMMENT '关联旅程编号',
  `token` VARCHAR(128) NULL DEFAULT NULL COMMENT '会诊/接收令牌',
  `source_institution_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '来源机构编码',
  `source_department_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '来源科室编码',
  `target_institution_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '目标机构编码',
  `target_department_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '目标科室编码',
  `priority` VARCHAR(8) NOT NULL DEFAULT 'P0' COMMENT '优先级：P0/P1',
  `status` VARCHAR(16) NOT NULL DEFAULT 'open' COMMENT '状态：open/accepted/done',
  `at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '待办生成时间',
  `due_at` DATETIME NULL DEFAULT NULL COMMENT '截止时间',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_todo_id` (`todo_id`),
  KEY `idx_assignee_status` (`assignee_id`, `status`),
  KEY `idx_patient` (`patient_id`),
  KEY `idx_token` (`token`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='移动协同待办表';
```

索引说明：`idx_assignee_status` 支撑「现场工作台」按当前医护 + 未办过滤；`idx_token` 支撑按会诊/接收令牌反查待办。

### 2.2 协同任务表 `coordination_tasks`

对应「现场工作台 · 任务协同」。协同任务为跨机构/跨角色的一次协作动作（转运、会诊、交接、评估）。

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |
|---------|-----------|------|------|------|
| 任务编号 | task_id | String | 是 | 任务唯一键 |
| 任务标题 | title | String | 是 | 任务标题 |
| 任务类型 | kind | String | 是 | transport / consult / handover / assessment |
| 患者 | patient_id / patient_name | String | 是 | 关联患者 |
| 来源机构/科室 | source_institution_id / source_department_id | String | 是 | 发起方 |
| 目标机构/科室 | target_institution_id / target_department_id | String | 是 | 接收方 |
| 责任人 | assignee_id / assignee_name | String | 是 | 责任人 staff |
| 车辆 | vehicle_id | String | 否 | 关联转运车辆 |
| 状态 | status | String | 是 | todo/doing/done |
| 进度关键点 | milestones | JSON | 否 | `[{key,at,by},...]` |
| 开始/截止 | started_at / due_at | DateTime | 否 | 计划执行时间 |

```sql
CREATE TABLE `coordination_tasks` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `task_id` VARCHAR(64) NOT NULL COMMENT '任务编号',
  `title` VARCHAR(128) NOT NULL DEFAULT '' COMMENT '任务标题',
  `kind` VARCHAR(16) NOT NULL DEFAULT '' COMMENT '类型：transport/consult/handover/assessment',
  `patient_id` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '关联患者编号',
  `patient_name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '关联患者姓名',
  `source_institution_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '来源机构编码',
  `source_department_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '来源科室编码',
  `target_institution_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '目标机构编码',
  `target_department_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '目标科室编码',
  `assignee_id` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '责任人 staff.id',
  `assignee_name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '责任人姓名',
  `vehicle_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '关联车辆编号',
  `status` VARCHAR(16) NOT NULL DEFAULT 'todo' COMMENT '状态：todo/doing/done',
  `milestones` JSON NULL COMMENT '进度关键点：[{key,at,by},...]',
  `started_at` DATETIME NULL DEFAULT NULL COMMENT '计划开始时间',
  `due_at` DATETIME NULL DEFAULT NULL COMMENT '计划截止时间',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_task_id` (`task_id`),
  KEY `idx_assignee_status` (`assignee_id`, `status`),
  KEY `idx_patient` (`patient_id`),
  KEY `idx_vehicle` (`vehicle_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='移动协同任务表';
```

索引说明：`idx_assignee_status` 支撑工作台任务看板；`idx_vehicle` 关联转运车辆考核。

### 2.3 手机重症接收单表 `mobile_receptions`

对应「手机重症接收」。基层现场上报重症患者后生成一条接收单，由接收机构科室在手机端查看详情并确认接收。

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |
|---------|-----------|------|------|------|
| 接收单号 | reception_id | String | 是 | 接收单唯一编号 |
| 接收入会令牌 | token | String | 是 | 接收令牌，URL 中 `{token}` |
| 旅程 | journey_id | String | 否 | 关联 `scenario.mobile.journeys[].id` |
| 患者 | patient_id / patient_name | String | 是 | 关联患者 |
| 性别 / 年龄 / 电话 | gender / age / phone | String/Integer | 是 | 患者概况 |
| 来源机构/科室 | source_institution_id / source_department_id | String | 是 | 上报方 |
| 病情类别 | category | String | 否 | 胸痛/卒中/创伤/其他 |
| 主诉 | complaint | String | 否 | 主诉 |
| 症状 | symptoms | JSON | 否 | `["胸痛（非创伤）", ...]` |
| 接收机构/科室 | accepted_institution_id / accepted_department_id | String | 否 | 确认接收后回填 |
| 接收医护 | accepted_by | String | 否 | 确认接收人 staff.id |
| 状态 | status | String | 是 | pending/accepted/rejected/timeout |
| 到院准备 | prep_checklist | JSON | 否 | `[{key,title,done,note},...]` |
| 接收时间 | accepted_at | DateTime | 否 | 确认接收时间 |

```sql
CREATE TABLE `mobile_receptions` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `reception_id` VARCHAR(64) NOT NULL COMMENT '接收单号',
  `token` VARCHAR(128) NOT NULL COMMENT '接收/入会令牌（URL token）',
  `journey_id` VARCHAR(64) NULL DEFAULT NULL COMMENT '关联旅程编号',
  `patient_id` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '关联患者编号',
  `patient_name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '关联患者姓名',
  `gender` VARCHAR(8) NOT NULL DEFAULT '' COMMENT '性别',
  `age` INT UNSIGNED NULL DEFAULT NULL COMMENT '年龄',
  `phone` VARCHAR(24) NOT NULL DEFAULT '' COMMENT '联系电话',
  `source_institution_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '来源机构编码',
  `source_department_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '来源科室编码',
  `category` VARCHAR(16) NOT NULL DEFAULT '' COMMENT '病情类别：胸痛/卒中/创伤/其他',
  `complaint` VARCHAR(255) NOT NULL DEFAULT '' COMMENT '主诉',
  `symptoms` JSON NULL COMMENT '症状数组：[...,...]',
  `accepted_institution_id` VARCHAR(32) NULL DEFAULT NULL COMMENT '接收机构编码',
  `accepted_department_id` VARCHAR(32) NULL DEFAULT NULL COMMENT '接收科室编码',
  `accepted_by` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '确认接收人 staff.id',
  `status` VARCHAR(16) NOT NULL DEFAULT 'pending' COMMENT '状态：pending/accepted/rejected/timeout',
  `prep_checklist` JSON NULL COMMENT '到院准备：[{key,title,done,note},...]',
  `accepted_at` DATETIME NULL DEFAULT NULL COMMENT '确认接收时间',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_reception_id` (`reception_id`),
  UNIQUE KEY `uk_token` (`token`),
  KEY `idx_patient` (`patient_id`),
  KEY `idx_status` (`status`),
  KEY `idx_target` (`accepted_institution_id`, `accepted_department_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='手机重症接收单表';
```

索引说明：`uk_token` 支撑按 URL 令牌直达接收详情；`idx_status` 支撑待接收队列；`idx_target` 支撑接收科室维度统计。

### 3.1 移动会诊待办

| 项目 | 内容 |
|------|------|
| 接口名称 | 移动会诊待办 |
| 请求方法 | GET |
| 请求路径 | `/api/v1/coordination/todos` |
| 接口描述 | 现场工作台 · 移动会诊待办列表：待会诊、待接收、待核实、待确认四类协同待办 |

| 字段名 | 类型 | 必填 | 说明 | 示例 |

```http
GET /api/v1/coordination/todos?status=open HTTP/1.1
```

### 3.4 科室接收确认

| 项目 | 内容 |
|------|------|
| 接口名称 | 科室接收 |
| 请求方法 | POST |
| 请求路径 | `/api/v1/mobile-reception/{token}/accept` |
| 接口描述 | 接收方选择机构 + 科室确认接收，推进接收单状态并回填到院准备 |
| 前端调用时机 | 接收详情页选择机构/科室后点击「确认接收」 |
| 前端渲染对应 | 接收成功提示、到院准备清单点亮 |
| 说明 | 前端为占位页，字段为规范设计 |

**Path 参数：** `token`（String，接收令牌）。

**Body 参数：**

| 字段名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| institutionId | String | 是 | 接收机构编码 | weiyuan |
| departmentId | String | 是 | 接收科室编码 | emergency |
| assigneeId | String | 否 | 确认接收医护（缺省取当前登录用户） | weiyuan-emergency-doctor |
| prepChecklist | Array | 否 | 到院准备勾选 | `[{ "key": "bed", "done": true, "note": "急诊 3 床" }]` |
| remark | String | 否 | 接收备注 | 已通知卒中小组 |

**请求示例：**

```http
POST /api/v1/mobile-reception/xun-2026-0002/accept HTTP/1.1

Content-Type: application/json

{
  "institutionId": "weiyuan",
  "departmentId": "emergency",
  "assigneeId": "weiyuan-emergency-doctor",
  "prepChecklist": [
    { "key": "bed", "done": true, "note": "急诊 3 床" },

  "remark": "已通知卒中小组"
}
```

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "receptionId": "MR-20260924-002",

    "status": "accepted",
    "acceptedInstitutionId": "weiyuan",
```

| code | 含义 |

## 5. 交互与边界说明

- **待办闭环**：接收待办（`transfer_confirm`）随 §3.4 确认接收（`accepted`）流转为 `done`；会诊待办随医生接诊流转。后端在状态流转时同步 `coordination_todos.status`。
- **幂等确认**：同一 `token` 的接收确认应幂等——已 `accepted` 时重复提交返回现有结果（或 409），不产生新记录。
- **超时保护**：接收单超过配置时限（如 30 分钟）未确认时置 `timeout`，避免现场长时间等待。
- **下拉联动**：前端选定机构后再请求 `/reception/departments?institutionId=`；机构下拉数据由 `organizations` 过滤「可接收重症」层级（center/city/county）得到。
- **令牌与旅程映射**：`token` 唯一定位接收单/旅程；同一患者可能先后在基层与县域产生多段旅程（`FIELD-001` 有会诊 + 转运两段），后端按 `token` 精确取当前段。

---

## 6. 前端对接注意事项

- **生命周期**：`/mobile-reception/:token` standalone 页 `onMounted` 拉取详情，确认接收后本地刷新状态徽标。
- **移动端展示**：接收详情为移动竖屏布局，`prepChecklist` 以勾选卡片渲染，消息流按 `at` 倒序。
- **空数据**：机构/科室下拉为空时降级显示「暂无可接收机构/科室」；无待办时工作台显示空状态。
- **错误提示**：令牌无效（404）提示「接收链接已失效，请重新获取」；重复确认（409）提示「该接收单已确认过」。
