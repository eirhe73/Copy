# 01 · 质控管理接口

## 1. 模块概述

| 项 | 内容 |
|----|------|
| 页面名称 | 质控整改看板（`/#/medical-quality`）、质控报表（`/#/medical-quality/reports`）、整改单详情（`/#/medical-quality/rectify/:id`）、质量指标（`/#/quality`） |
| 核心功能 | 质控标准与合规率、SLA 时效、整改台账、差距分析与销号、质控报表与导出、质量指标与趋势 |
| 涉及实体 | 质控标准（qc_standard）、质控抽检记录（qc_check_record）、SLA 规则（sla_rule）、SLA 记录（sla_record） |
| 数据源 | `public/api/qc-standards.json`、`public/api/qc-sla.json` |

对应路由（`routes/meta.ts`）：`/medical-quality`（整改台账、级别分布、超期预警）、`/medical-quality/reports`（筛查覆盖、机构统计、导出 CSV）、`/medical-quality/rectify/:id`（差距分析、原因与措施、销号流程）、`/quality`（指标看板、趋势对比）。

## 2. 数据模型定义

### 2.1 质控标准表 `qc_standards`

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |
|---------|-----------|------|------|------|
| 标准编号 | standard_id | String | 是 | 如 QC-ER-001 |
| 标准名 | name | String | 是 | 如「120出车响应」 |
| 目标 | target | String | 是 | 达标要求描述 |
| 采样周期 | sample_period | String | 是 | 月/季/年 |
| 合规率 | compliance_rate | Decimal(5,4) | 是 | 0~1 |
| 版本 | version | String | 是 | 如 2026-Q4-v1 |

```sql
CREATE TABLE `qc_standards` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `standard_id` VARCHAR(32) NOT NULL COMMENT '标准编号，如 QC-ER-001',
  `name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '标准名称',
  `target` VARCHAR(255) NOT NULL DEFAULT '' COMMENT '达标要求',
  `sample_period` VARCHAR(16) NOT NULL DEFAULT '月' COMMENT '采样周期',
  `compliance_rate` DECIMAL(5,4) NOT NULL DEFAULT 0 COMMENT '合规率 0~1',
  `version` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '标准版本',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_standard_version` (`standard_id`, `version`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='质控标准表';
```

### 2.2 质控抽检记录表 `qc_check_records`

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |
|---------|-----------|------|------|------|
| 抽检时间 | check_at | DateTime | 是 | 抽检时间 |
| 标准 | standard_id | String | 是 | 关联标准 |
| 是否达标 | ok | Boolean | 是 | 达标标记 |
| 备注 | note | String | 否 | 抽检说明 |

```sql
CREATE TABLE `qc_check_records` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `standard_id` VARCHAR(32) NOT NULL COMMENT '标准编号',
  `check_at` DATETIME NOT NULL COMMENT '抽检时间',
  `ok` TINYINT(1) NOT NULL DEFAULT 1 COMMENT '是否达标：0否1是',
  `note` VARCHAR(255) NOT NULL DEFAULT '' COMMENT '抽检备注',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  PRIMARY KEY (`id`),
  KEY `idx_standard_time` (`standard_id`, `check_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='质控抽检记录表';
```

### 2.3 SLA 规则表 `sla_rules` 与记录表 `sla_records`

```sql
CREATE TABLE `sla_rules` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `rule_id` VARCHAR(32) NOT NULL COMMENT '规则编号，如 SLA-ALERT',
  `name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '规则名，如 预警后到床',
  `limit_minutes` INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '时限（分钟）',
  `audience` VARCHAR(128) NOT NULL DEFAULT '' COMMENT '数据受众说明',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_rule_id` (`rule_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='SLA时效规则表';

CREATE TABLE `sla_records` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `record_id` VARCHAR(64) NOT NULL COMMENT '记录编号，如 SLA-20261012-01',
  `kind` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '类型，如 预警到床/出警到院',
  `rule_id` VARCHAR(32) NOT NULL COMMENT '规则编号',
  `subject` VARCHAR(128) NOT NULL DEFAULT '' COMMENT '主体（患者/车辆）',
  `owner` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '责任人',
  `role_view` VARCHAR(16) NOT NULL DEFAULT 'doctor' COMMENT '数据权限角色：doctor/director',
  `started_at` DATETIME NOT NULL COMMENT '开始时间',
  `arrived_at` DATETIME NULL DEFAULT NULL COMMENT '到达时间',
  `limit_minutes` INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '时限（分钟）',
  `used_minutes` INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '已用（分钟）',
  `overtime` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '是否超时：0否1是',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_record_id` (`record_id`),
  KEY `idx_role_rule` (`role_view`, `rule_id`),
  KEY `idx_started` (`started_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='SLA时效记录表';
```

索引说明：`idx_role_rule` 支撑「当班医生看自己 / 管理者看全院」的数据权限过滤；`idx_started` 支撑时间范围查询。

### 3.1 获取质控标准与近期抽检

| 项目 | 内容 |
|------|------|

## 4. 数据模型补充（整改 / 报表 / 质量指标）

> 以下实体前端无独立 Mock JSON，字段依据 `routes/meta.ts` 模块描述 + 质控业务域 + 前端打包构件中「质控整改台账」CSV 导出列与整改单详情渲染字段（差距分析、原因分类、原因分析、整改措施、销号流程）回读推导。除「整改单」外均为**规范设计**。

### 4.1 整改单表 `qc_rectifies`

| 前端展示 | 数据库字段 | 类型 | 必填 | 示例 | 说明 |
|---------|-----------|------|------|------|------|
| 整改编号 | rectify_id | String | 是 | `ZG02600001` | 唯一编号 |
| 问题标题 | title | String | 是 | `卒中患者 DNT 中位时间超出目标值` | 问题标题 |
| 问题描述 | description | Text | 否 | — | 问题详情 |
| 问题来源 | source | String | 是 | `alert` | 见 §6 枚举 |
| 级别 | level | TinyInt | 是 | `1` | 1严重/2一般/3轻微 |
| 状态 | status | String | 是 | `closed` | 见 §6 枚举 |
| 责任人 | owner_name | String | 是 | `周颖（演示）` | 责任人姓名 |
| 所属机构 | owner_org | String | 是 | `weiyuan` | 关联 organization.id |
| 科室 | owner_dept | String | 是 | `neurology` | 关联 department.id |
| 关联质控标准 | standard_id | String | 否 | `QC-ER-003` | 关联 qc_standards |
| 关联时限规则 | rule_id | String | 否 | `SLA-ALERT` | 关联 sla_rules |
| 发现时间 | found_at | DateTime | 是 | `2026-10-12T10:00:00+08:00` | 发现时间 |
| 整改期限 | deadline | DateTime | 是 | 同左 | 整改截止时间 |
| 销号时间 | closed_at | DateTime | 否 | 同左 | 销号时间 |
| 差距分析 | standard_gap | String | 是 | `目标 DNT 中位时间 ≤45 分钟，实际 58 分钟` | 差距分析 |
| 原因分类 | cause_category | String | 是 | `流程制度` | 见 §6 枚举 |
| 原因分析 | cause_analysis | Text | 是 | — | 原因分析 |
| 整改措施 | measure | Text | 是 | — | 整改措施与责任人 |
| 复评人 | reviewer_name | String | 否 | `王慧敏（演示）` | 复评人 |
| 数据权限角色 | role_view | String | 是 | `doctor` | `doctor`/`director` |

```sql
CREATE TABLE `qc_rectifies` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `rectify_id` VARCHAR(32) NOT NULL COMMENT '整改编号，如 ZG02600001',
  `title` VARCHAR(128) NOT NULL DEFAULT '' COMMENT '问题标题',
  `description` TEXT NULL COMMENT '问题描述',
  `source` VARCHAR(32) NOT NULL DEFAULT 'manual' COMMENT '问题来源：alert/pathwayTimeout/inspection/complaint/manual',
  `level` TINYINT UNSIGNED NOT NULL DEFAULT 2 COMMENT '级别：1严重2一般3轻微',
  `status` VARCHAR(16) NOT NULL DEFAULT 'pending' COMMENT '状态：pending/rectifying/reviewing/closed',
  `owner_name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '责任人姓名',
  `owner_org` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '所属机构ID',
  `owner_dept` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '科室ID',
  `standard_id` VARCHAR(32) NULL DEFAULT NULL COMMENT '关联质控标准编号',
  `rule_id` VARCHAR(32) NULL DEFAULT NULL COMMENT '关联时限规则编号',
  `found_at` DATETIME NOT NULL COMMENT '发现时间',
  `deadline` DATETIME NOT NULL COMMENT '整改期限',
  `closed_at` DATETIME NULL DEFAULT NULL COMMENT '销号时间',
  `standard_gap` VARCHAR(255) NOT NULL DEFAULT '' COMMENT '差距分析',
  `cause_category` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '原因分类：流程制度/设备设施/培训不足/沟通协作/人员配备',
  `cause_analysis` TEXT NULL COMMENT '原因分析',
  `measure` TEXT NULL COMMENT '整改措施',
  `reviewer_name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '复评人',
  `role_view` VARCHAR(16) NOT NULL DEFAULT 'doctor' COMMENT '数据权限角色：doctor/director',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `deleted_at` DATETIME NULL DEFAULT NULL COMMENT '软删除时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_rectify_id` (`rectify_id`),
  KEY `idx_level_status` (`level`, `status`),
  KEY `idx_role_view` (`role_view`),
  KEY `idx_owner_org_dept` (`owner_org`, `owner_dept`),
  KEY `idx_status_deadline` (`status`, `deadline`),
  KEY `idx_found_at` (`found_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='质控整改单表';
```

索引说明：
- `uk_rectify_id`：整改编号唯一，前端列表、详情、销号均按编号定位。
- `idx_level_status`：级别分布 + 状态筛选（质控看板）。
- `idx_status_deadline`：待整改/整改中的`超期预警`（未销号且 `deadline < now`）。
- `idx_role_view`：复用 SLA 的数据权限维度 `roleView`（doctor 看本人、director 看全院）。
- `idx_owner_org_dept`：按机构/科室统计与下钻。

### 4.4 质量指标定义表 `quality_metrics` 与趋势表 `quality_metric_trends`

> 质量指标（`/#/quality` 运行统计）字段为规范设计；指标口径沿用报表目录（急救时效、绿色通道达标率、业务量、病种分布、机构协同）。

```sql
CREATE TABLE `quality_metrics` (

  `unit` VARCHAR(16) NOT NULL DEFAULT '' COMMENT '单位：分钟/%/例',
  `target` DECIMAL(12,4) NULL DEFAULT NULL COMMENT '目标值',
  `direction` VARCHAR(8) NOT NULL DEFAULT 'lower' COMMENT '阈值方向：lower越小越好/higher越大越好',
  `owner` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '指标负责人',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_metric_id` (`metric_id`)

CREATE TABLE `quality_metric_trends` (

  `baseline_value` DECIMAL(12,4) NULL DEFAULT NULL COMMENT '对比基准值（环比/同比）',
  `delta` DECIMAL(12,4) NULL DEFAULT NULL COMMENT '较基准变化量',
  `generated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '生成时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_metric_point` (`metric_id`, `period`, `point_date`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='质量指标趋势表';
```

## 6. 状态与枚举值

### 6.1 整改问题来源 `source`

| code（存储） | label（显示） | 说明 |
|-------------|--------------|------|
| `alert` | 规则预警 | 质控规则/指标预警触发 |
| `pathwayTimeout` | 绿色通道超时 | 五大中心路径环节超时 |
| `inspection` | 质控检查 | 质控部门检查发现 |
| `complaint` | 投诉反馈 | 投诉/反馈渠道转办 |
| `manual` | 人工登记 | 人工手动登记 |

### 6.2 整改级别 `level`

| code | label | 说明 |
|------|-------|------|
| 1 | 严重 | 影响患者安全或核心时效达标，需优先整改 |
| 2 | 一般 | 影响流程质量，限期整改 |
| 3 | 轻微 | 轻微缺陷，按常规周期整改 |

### 6.3 整改状态 `status`

| code（存储） | label（显示） | 说明 |
|-------------|--------------|------|
| `pending` | 待整改 | 刚登记，尚未开始整改 |
| `rectifying` | 整改中 | 已开始整改，措施落实中 |
| `reviewing` | 待复评 | 已提交复评，等待复评人结论 |
| `closed` | 已销号 | 复评通过并销号，闭环终点 |

### 6.4 销号流转动作 `action`

| code | label | 说明 |
|------|-------|------|
| `start` | 开始整改 | pending → rectifying |
| `submit` | 提交复评 | rectifying → reviewing |
| `approve` | 复评通过并销号 | reviewing → closed |
| `reject` | 退回整改 | reviewing → rectifying |

### 6.5 数据权限角色 `roleView`

| code | 说明 |
|------|------|
| `doctor` | 当班医生：仅看本人负责的 SLA/整改记录 |
| `director` | 管理者（护士长/院长/质控）：查看全院 |

> `roleView` 与 SLA 模块 `sla_records.role_view` 保持一致，质控整改单、指标看板复用同一权限维度。
