# 03 · 基层医声接口

## 1. 模块概述

| 项 | 内容 |
|----|------|
| 页面名称 | 基层医声 Dr.（`/#/dr`） |
| 核心功能 | 基层反馈、问题上报、协作消息（基层 ↔ 上级语音 / 文字协作沟通） |
| 涉及实体 | 基层反馈（dr_post）、协作消息（dr_message） |
| 数据源 | 无独立 Mock（`routes/meta.ts` `/dr` 模块描述 + `dr-ui-enhance.js` 播放列表/连续播放增强） |

对应路由（`routes/meta.ts`）：`/dr`（基层反馈 / 问题上报 / 协作消息）。增强脚本 `dr-ui-enhance.js` 处理「连续播放」并入播放列表标题栏，表明协作消息以可连续收听的语音（医声）流为主。

> 本章接口无独立 Mock JSON，全部字段依据 `routes/meta.ts` `/dr` 模块描述 + 基层协作业务域 + `scenario.json` 机构数据推导，标注「**字段为规范设计**」。

## 2. 数据模型定义

### 2.1 基层反馈表 `dr_posts`

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |
|---------|-----------|------|------|------|
| 反馈编号 | post_id | String | 是 | 反馈 / 问题业务编号 |
| 类型 | category | Integer | 是 | 0基层反馈 1问题上报 |
| 标题 / 内容 | title / content | String | 是 | 反馈标题与正文 |
| 上报机构 | institution_id / institution_name | String | 是 | 基层机构编号与名称 |
| 上报科室 | department | String | 是 | 上报科室 |
| 上报人 | reporter_id / reporter_name | String | 是 | 上报人账号与姓名 |
| 联系方式 | contact | String | 否 | 联系电话 / 微信 |
| 优先级 | priority | Integer | 是 | 0普通 1紧急 |
| 状态 | status | Integer | 是 | 0待处理 1已回复 2已办结 |
| 回复 | reply / replied_by / replied_at | - | 否 | 回复内容 / 回复人 / 回复时间 |
| 附件 | attachments | JSON | 否 | 附件地址列表 |
| 上报时间 | created_at | DateTime | 是 | 上报时间 |

```sql
CREATE TABLE `dr_posts` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `post_id` VARCHAR(64) NOT NULL COMMENT '反馈/问题业务编号',
  `category` TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '类型：0基层反馈1问题上报',
  `title` VARCHAR(128) NOT NULL DEFAULT '' COMMENT '标题',
  `content` TEXT NOT NULL COMMENT '内容',
  `institution_id` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '上报机构编号',
  `institution_name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '上报机构名称',
  `department` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '上报科室',
  `reporter_id` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '上报人账号',
  `reporter_name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '上报人姓名',
  `contact` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '联系方式',
  `priority` TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '优先级：0普通1紧急',
  `status` TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '状态：0待处理1已回复2已办结',
  `reply` TEXT NULL COMMENT '回复内容',
  `replied_by` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '回复人',
  `replied_at` DATETIME NULL DEFAULT NULL COMMENT '回复时间',
  `attachments` JSON NULL COMMENT '附件地址列表',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '上报时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_post_id` (`post_id`),
  KEY `idx_category_status` (`category`, `status`),
  KEY `idx_institution` (`institution_id`),
  KEY `idx_created` (`created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='基层反馈/问题上报表';
```

索引说明：

- `uk_post_id`：反馈 / 问题编号唯一，支撑按编号定位单条反馈。
- `idx_category_status`：反馈列表按「类型 + 状态」组合筛选（基层反馈 / 问题上报 Tab）。
- `idx_institution`：按上报机构分桶（机构维度统计各基层反馈数）。
- `idx_created`：反馈列表按上报时间倒序分页。

### 2.2 协作消息表 `dr_messages`

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |
|---------|-----------|------|------|------|
| 消息编号 | message_id | String | 是 | 消息唯一编号 |
| 协作链路 | thread_id | String | 是 | 同一协作线程序列（收 / 发同链） |
| 发送机构 | institution_id / institution_name | String | 是 | 发送机构编号与名称 |
| 发送人 | sender_id / sender_name | String | 是 | 发送人账号与姓名 |
| 消息类型 | kind | Integer | 是 | 0文字 1语音 2图片 3文件 |
| 文字内容 | content | Text | 否 | 文字消息正文 |
| 媒体地址 | media_url | String | 否 | 语音 / 图片 / 文件 URL |
| 语音时长 | duration_sec | Integer | 否 | 语音时长（秒），配合连续播放 |
| 已读 | is_read | Integer | 是 | 0未读 1已读 |
| 发送时间 | created_at | DateTime | 是 | 发送时间 |

```sql
CREATE TABLE `dr_messages` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `message_id` VARCHAR(64) NOT NULL COMMENT '消息编号',
  `thread_id` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '协作线程序列（收/发同链）',
  `institution_id` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '发送机构编号',
  `institution_name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '发送机构名称',
  `sender_id` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '发送人账号',
  `sender_name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '发送人姓名',
  `kind` TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '消息类型：0文字1语音2图片3文件',
  `content` TEXT NULL COMMENT '文字消息正文',
  `media_url` VARCHAR(255) NOT NULL DEFAULT '' COMMENT '语音/图片/文件 URL',
  `duration_sec` INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '语音时长（秒）',
  `is_read` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '已读：0未读1已读',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '发送时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_message_id` (`message_id`),
  KEY `idx_thread` (`thread_id`),
  KEY `idx_institution` (`institution_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='协作消息表';
```

索引说明：

- `uk_message_id`：消息编号唯一。
- `idx_thread`：按协作链路拉取消息流（消息流页排序展示）。
- `idx_institution`：按机构筛选协作消息。

## 4. 状态与枚举值

### 4.1 反馈类型 `category`

| 存储值 | 显示文本 |
|--------|---------|
| `FEEDBACK` | 基层反馈 |
| `ISSUE` | 问题上报 |

### 4.2 反馈优先级 `priority`

| code（存储） | 显示文本 |
|-------------|---------|
| 0 | 普通 |
| 1 | 紧急 |

### 4.3 反馈状态 `status`

| code（存储） | 常量 | label（显示） |
|-------------|------|--------------|
| 0 | `PENDING` | 待处理 |
| 1 | `REPLIED` | 已回复 |
| 2 | `RESOLVED` | 已办结 |

状态流转：`PENDING → REPLIED → RESOLVED`。

### 4.4 消息类型 `kind`

| code（存储） | 显示文本 | 说明 |
|-------------|---------|------|
| 0 | 文字 | `content` 为正文 |
| 1 | 语音 | `media_url` 为音频，携 `duration_sec` |
| 2 | 图片 | `media_url` 为图片地址 |
| 3 | 文件 | `media_url` 为文件地址 |

## 5. 交互与边界说明

- **医声语音流**：协作消息以语音为主，语音消息携带 `durationSec`，前端按「连续播放」开关顺序收听（见 `dr-ui-enhance.js` 将连续播放控件并入播放列表标题栏）。
- **链路归属**：同一协作对象之间的收发消息共享 `thread_id`；首个消息缺省新建链路并回传 `threadId`，后续消息沿用。
- **媒体上传**：语音 / 图片 / 文件类消息需先经文件上传接口落盘，再以 `media_url` 提交消息（文件上传接口见系统 / 云盘相关模块）。
- **归档口径**：问题上报以「待处理 → 已回复 → 已办结」推进；基层反馈与问题上报共用一张表，靠 `category` 区分 Tab。
- **权限边界**：基层机构仅可见 / 维护本机构上报的反馈；上级（管理员）可跨机构检索与回复。

## 6. 前端对接注意事项

- **Tab 切换**：`/#/dr` 页按「基层反馈 / 问题上报 / 协作消息」分区，反馈列表与消息流各自独立拉取，不混用同一接口。
- **连续播放**：消息流语音列表提供「连续播放」开关，选中后依次自动播放未读语音。
- **空状态**：无反馈时显示空态；无协作消息时提示「暂无协作消息」。
- **错误提示**：上报标题 / 内容为空提示「请填写标题 / 内容」；语音消息未上传媒体提示「请先录制或上传语音」。
- **轮询**：协作消息面板建议 10s 轮询（演示未真实轮询），保证基层与上级消息及时同步。
