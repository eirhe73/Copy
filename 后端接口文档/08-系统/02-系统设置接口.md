# 02 · 系统设置接口

## 1. 页面/模块概述

| 项 | 内容 |
|----|------|
| 页面名称 | 系统设置（`/#/settings`）、手机通知演示（`/#/phone`） |
| 核心功能 | 演示数据重置、通知渠道配置、偏好配置（读取/保存） |
| 涉及实体 | 通知渠道（notification_channel）、系统偏好（system_preference） |
| 数据源 | 路由 `src/routes/meta.ts` `/settings`（演示数据重置、通知渠道、偏好配置）与 `/phone`（短信/微信服务通知 UI） |

对应路由（`routes/meta.ts`）：`/settings`（`group='系统'`，standalone 非，展示在侧栏）；`/phone`（standalone，短信/微信服务通知 UI）。前端均为占位脚手架，无独立 Mock JSON，**字段为规范设计**。

## 2. 数据模型定义

### 2.1 通知渠道表 `notification_channels`

对应「系统设置 · 通知渠道」。消息中心（[06-机构与配置/04-消息中心接口](../../06-机构与配置/04-消息中心接口.md)）的微信/短信触达通道在此统一配置启停与参数。

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |
|---------|-----------|------|------|------|
| 渠道编号 | channel_id | String | 是 | 渠道唯一键 |
| 渠道代码 | channel | String | 是 | wechat / sms / inapp |
| 显示名 | name | String | 是 | 如「微信服务通知」 |
| 是否启用 | enabled | Boolean | 是 | 0 关 / 1 开 |
| 渠道配置 | config | JSON | 否 | 模板、签名、回调等参数 |
| 排序 | sort | Integer | 否 | 显示顺序 |
| 更新时间 | updated_at | DateTime | 是 | 最近修改 |

```sql
CREATE TABLE `notification_channels` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `channel_id` VARCHAR(32) NOT NULL COMMENT '渠道编号',
  `channel` VARCHAR(16) NOT NULL COMMENT '渠道代码：wechat/sms/inapp',
  `name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '渠道显示名',
  `enabled` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '是否启用：0关1开',
  `config` JSON NULL COMMENT '渠道参数：模板/签名/回调等',
  `sort` INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '显示排序',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_channel` (`channel`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='通知渠道配置表';
```

索引说明：`uk_channel` 保证渠道代码唯一；渠道枚举固定（wechat/sms/inapp），无需高频检索索引。

### 2.2 系统偏好表 `system_preferences`

对应「系统设置 · 偏好配置」。存储当前用户 / 全局的界面与通知偏好（主题、语言、提醒开关等），采用 `(user_id, pref_key)` 键值 + `pref_value` JSON。

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |
|---------|-----------|------|------|------|
| 归属用户 | user_id | String | 是 | 空字符串表示全局默认 |
| 偏好键 | pref_key | String | 是 | 如 `theme` / `locale` / `notification` |
| 偏好值 | pref_value | JSON | 是 | 结构化偏好值 |
| 更新时间 | updated_at | DateTime | 是 | 最近修改 |

```sql
CREATE TABLE `system_preferences` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `user_id` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '归属用户账号（空=全局默认）',
  `pref_key` VARCHAR(64) NOT NULL COMMENT '偏好键：theme/locale/notification等',
  `pref_value` JSON NULL COMMENT '偏好值（结构化）',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_key` (`user_id`, `pref_key`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='系统偏好配置表';
```

索引说明：`uk_user_key` 保证同一用户同一偏好键唯一，支撑「读取→默认值合并→保存 upsert」。

## 3. 接口清单

### 3.1 演示数据重置

| 项目 | 内容 |
|------|------|
| 接口名称 | 演示数据重置 |
| 请求方法 | POST |
| 请求路径 | `/api/v1/settings/demo-reset` |
| 接口描述 | 重置演示/mock 数据到初始态（`scenario.json` 快照），可选按域重置 |
| 前端调用时机 | 系统设置「演示数据重置」按钮确认后 |
| 前端渲染对应 | 重置结果提示（各域重置条数） |
| 说明 | 前端为占位页，字段为规范设计；重置覆盖 `state` 与顶层 `mobile` 各集合 |

**Body 参数：**

| 字段名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| scope | String | 否 | 重置范围，逗号分隔，缺省 all | patients,staff,beds,events,mobile |
| resetTime | String | 否 | 重置锚点时间（ISO 8601） | 2026-10-13T09:00:00+08:00 |

**请求示例：**

```http
POST /api/v1/settings/demo-reset HTTP/1.1
Authorization: Bearer {token}
Content-Type: application/json

{
  "scope": "all",
  "resetTime": "2026-10-13T09:00:00+08:00"
}
```

**响应示例（成功）：**

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "resetAt": "2026-10-13T09:00:00+08:00",
    "counts": {
      "patients": 12,
      "staff": 24,
      "beds": 48,
      "events": 45,
      "mobile": { "journeys": 6, "dispatches": 2, "consultationRequests": 8 }
    }
  }
}
```

**错误码：**

| code | 含义 |
|------|------|
| 200 | 成功 |
| 400 | scope 取值非法 |
| 401 | 未认证或 Token 失效 |
| 403 | 无重置权限（仅 director） |

### 3.4 更新偏好

| 项目 | 内容 |
|------|------|
| 接口名称 | 更新偏好 |
| 请求方法 | PUT |
| 请求路径 | `/api/v1/settings/preferences` |

```http
{

```

**响应示例（成功）：**

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "theme": "dark",
    "locale": "zh-CN",
    "notification": {
      "tone": "warn",

      "sms": true,
      "inapp": true
```

## 4. 状态与枚举值

### 4.1 通知渠道 `channel`

| code | 显示 | 说明 |
|------|------|------|
| `wechat` | 微信服务通知 | 微信模板消息 |
| `sms` | 短信通知 | 短信触达 |
| `inapp` | 站内消息 | 站内 P0 闭环通道 |

### 4.2 偏好键 `pref_key`

| code | 说明 | 取值示例 |
|------|------|---------|
| `theme` | 主题 | light / dark |
| `locale` | 语言 | zh-CN / en-US |
| `notification` | 通知偏好 | `{tone, wechat, sms, inapp}` |
| `list_density` | 列表密度 | comfortable / compact |

## 5. 交互与边界说明

- **重置权限**：`demo-reset` 属高危操作，仅 `roleView=director` 可执行；重置过程应记录操作人（审计）。
- **重置范围**：`scope=all` 覆盖 `state.patients/staff/beds/events` 与顶层 `mobile`（journeys/dispatches/consultationRequests 等）；重置后前端轮询接口应能立即读到初始快照。
- **偏好合并**：读取偏好时用户未配置的键回退全局默认；保存为增量 upsert（不覆盖未传入键）。
- **渠道与消息联动**：消息中心的 P0 站内闭环独立于 `wechat`/`sms` 通道开关；关闭 `wechat`/`sms` 不影响站内待办流转（对齐消息中心 §4.3「通道失败不影响任务流转」）。

---

## 6. 前端对接注意事项

- **重置确认**：`demo-reset` 触发前前端弹出二次确认，避免误触。
- **偏好即时生效**：保存成功后前端直接以响应结果刷新主题/语言，无需重新登录。
- **渠道开关**：关闭 `wechat`/`sms` 后，消息中心服务通知角标相应隐藏对应通道。
- **空数据**：无偏好记录时返回全局默认；无渠道配置时返回空数组。
