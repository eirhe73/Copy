# 01 · 预警中心接口

## 1. 模块概述

| 项 | 内容 |
|----|------|
| 页面名称 | 预警中心（`/#/warning`） |
| 核心功能 | NEWS/体征预警、检验危急值、处置闭环、预警统计 |
| 涉及实体 | 预警趋势（warning_trend）、预警闭环（warning_closed_loop） |
| 数据源 | `public/api/warning-demo.json` |

对应路由（`routes/meta.ts`）：`/warning`（NEWS/体征预警、检验危急值、处置闭环、预警统计）。

---

## 2. 数据模型定义

### 2.1 预警趋势表 `warning_trends` 与闭环表 `warning_closed_loop`

```sql
CREATE TABLE `warning_trends` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `trend_id` VARCHAR(32) NOT NULL COMMENT '趋势编号，如 TR-01',
  `patient_label` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '患者标签，如 心内科 12床',
  `metric` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '指标，如 NEWS/SpO₂/心率',
  `current_value` DECIMAL(10,2) NOT NULL DEFAULT 0 COMMENT '当前值',
  `predicted_value` DECIMAL(10,2) NOT NULL DEFAULT 0 COMMENT '预测值',
  `within_minutes` INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '预测分钟',
  `note` VARCHAR(255) NOT NULL DEFAULT '' COMMENT '说明',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_trend_id` (`trend_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='预警趋势表';

CREATE TABLE `warning_closed_loop` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `stage` VARCHAR(32) NOT NULL COMMENT '阶段：预警触发/护士确认/医生到床/干预完成',
  `count` INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '数量',
  `stat_date` DATE NOT NULL COMMENT '统计日期',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_stage_date` (`stage`, `stat_date`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='预警处置闭环表';
```

### 2.2 预警主表 `warnings`

| 前端展示 | 数据库字段 | 类型 | 必填 | 示例 | 说明 |
|---------|-----------|------|------|------|------|
| 预警编号 | warning_no | String | 是 | `WARN-20261012-001` | 预警唯一编号 |
| 患者 | patient_id / patient_label | String | 是 | `DEMO-001` / `心内科 12床` | 患者 ID + 床号标签 |
| 类别 | category | String | 是 | `NEWS` | 见 4.2 类别枚举 |
| 标题 | title | String | 是 | `NEWS评分关注` | 预警标题 |
| 指标 | metric | String | 否 | `NEWS` | 关联指标：NEWS/SpO₂/心率 |
| 当前值 | current_value | Decimal(10,2) | 否 | `7` | 触发时的测量值 |
| 阈值 | threshold | String | 否 | `≥ 5 触发关注` | 阈值/参考范围 |
| 等级 | level | String | 是 | `urgent` | 见 4.3 等级枚举 |
| 状态 | status | String | 是 | `new` | 见 4.4 状态枚举 |
| 机构/科室 | institution_id / department_id | String | 否 | `weiyuan` / `icu` | 所属机构与科室 |
| 触发时间 | occurred_at | DateTime | 是 | `2026-10-12T14:58:00+08:00` | 预警触发时间 |

```sql
CREATE TABLE `warnings` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `warning_no` VARCHAR(32) NOT NULL COMMENT '预警编号，如 WARN-20261012-001',
  `patient_id` VARCHAR(32) NOT NULL COMMENT '患者ID，关联 patients.id',
  `patient_label` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '患者标签，如 心内科 12床',
  `category` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '预警类别：NEWS/CRITICAL_VALUE/VASOACTIVE/COAG',
  `title` VARCHAR(128) NOT NULL DEFAULT '' COMMENT '预警标题',
  `metric` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '关联指标：NEWS/SpO₂/心率等',
  `current_value` DECIMAL(10,2) NULL DEFAULT NULL COMMENT '当前测量值',
  `threshold` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '阈值或参考范围',
  `level` VARCHAR(16) NOT NULL DEFAULT 'warning' COMMENT '等级：urgent紧急/warning关注',
  `status` VARCHAR(16) NOT NULL DEFAULT 'new' COMMENT '状态：new/acknowledged/treating/resolved',
  `institution_id` VARCHAR(32) NULL DEFAULT NULL COMMENT '机构ID',
  `department_id` VARCHAR(32) NULL DEFAULT NULL COMMENT '科室ID',
  `occurred_at` DATETIME NOT NULL COMMENT '预警触发时间',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_warning_no` (`warning_no`),
  KEY `idx_patient` (`patient_id`),
  KEY `idx_status` (`status`),
  KEY `idx_category_occurred` (`category`, `occurred_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='预警主表';
```

索引说明：
- `uk_warning_no`：预警编号全局唯一，支持详情/处置按编号定位。
- `idx_patient`：患者维度反查（患者详情页「预警与处置」列表）。
- `idx_status`：预警列表按状态快速过滤。
- `idx_category_occurred`：按类别 + 时间做统计报表与趋势聚合。

### 2.3 预警处置闭环记录表 `warning_dispose_records`

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |
|---------|-----------|------|------|------|
| 关联预警 | warning_id / warning_no | BigInt/String | 是 | 关联 warnings 主键与编号 |
| 阶段 | stage | String | 是 | 预警触发/护士确认/医生到床/干预完成 |
| 处置说明 | note | String | 否 | 处置意见 |
| 操作人 | actor_id / actor_name | String | 是 | 操作人 ID 与姓名 |
| 操作时间 | acted_at | DateTime | 是 | 阶段操作时间 |

```sql
CREATE TABLE `warning_dispose_records` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `warning_id` BIGINT UNSIGNED NOT NULL COMMENT '关联预警 warnings.id',
  `warning_no` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '预警编号冗余',
  `stage` VARCHAR(32) NOT NULL COMMENT '阶段：预警触发/护士确认/医生到床/干预完成',
  `note` VARCHAR(255) NOT NULL DEFAULT '' COMMENT '处置说明',
  `actor_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '操作人ID',
  `actor_name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '操作人姓名',
  `acted_at` DATETIME NOT NULL COMMENT '操作时间',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  PRIMARY KEY (`id`),
  KEY `idx_warning` (`warning_id`),
  KEY `idx_stage_acted` (`stage`, `acted_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='预警处置闭环记录表';
```

索引说明：
- `idx_warning`：详情页回读某条预警的完整闭环轨迹。
- `idx_stage_acted`：闭环明细「按阶段 + 时间」聚合与列表检索。

### 2.4 检验危急值表 `critical_values`

> 数据来源：`summary24h.criticalValue` 仅给出 24h 危急值计数；危急值明细字段为**规范设计**（参照检验科室危急值上报通用结构），后续接入 LIS 后回填。

| 前端展示 | 数据库字段 | 类型 | 必填 | 示例 | 说明 |
|---------|-----------|------|------|------|------|
| 危急值编号 | critical_no | String | 是 | `CV-20261012-001` | 唯一编号 |
| 患者 | patient_id / patient_label | String | 是 | `DEMO-002` / `急诊 3床` | 患者 ID + 标签 |
| 检验项目 | item_name | String | 是 | `钾离子 K+` | 项目名称 |
| 结果值 | result_value | String | 是 | `6.2` | 实测值 |
| 单位 | unit | String | 否 | `mmol/L` | 计量单位 |
| 参考范围 | ref_range | String | 否 | `3.5–5.3` | 正常参考范围 |
| 危急界限 | critical_range | String | 是 | `> 6.0` | 危急值阈值 |
| 标本类型 | specimen | String | 否 | `血清` | 标本类型 |
| 等级 | level | String | 是 | `urgent` | 见 4.3 等级枚举 |
| 处理状态 | status | String | 是 | `pending` | 见 4.5 危急值状态 |
| 报告时间 | reported_at | DateTime | 是 | `2026-10-12T14:20:00+08:00` | 报告时间 |

```sql
CREATE TABLE `critical_values` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `critical_no` VARCHAR(32) NOT NULL COMMENT '危急值编号，如 CV-20261012-001',
  `patient_id` VARCHAR(32) NOT NULL COMMENT '患者ID',
  `patient_label` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '患者标签',
  `item_name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '检验项目名称',
  `result_value` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '结果值',
  `unit` VARCHAR(16) NOT NULL DEFAULT '' COMMENT '单位',
  `ref_range` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '参考范围',
  `critical_range` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '危急值界限',
  `specimen` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '标本类型',
  `level` VARCHAR(16) NOT NULL DEFAULT 'urgent' COMMENT '等级：urgent紧急/warning关注',
  `status` VARCHAR(16) NOT NULL DEFAULT 'pending' COMMENT '状态：pending/notified/handled',
  `institution_id` VARCHAR(32) NULL DEFAULT NULL COMMENT '机构ID',
  `department_id` VARCHAR(32) NULL DEFAULT NULL COMMENT '科室ID',
  `reported_at` DATETIME NOT NULL COMMENT '报告时间',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_critical_no` (`critical_no`),
  KEY `idx_patient` (`patient_id`),
  KEY `idx_status_reported` (`status`, `reported_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='检验危急值表';
```

索引说明：
- `uk_critical_no`：危急值编号唯一。
- `idx_patient`：患者维度反查危急值历史。
- `idx_status_reported`：危急值待处理队列按状态 + 报告时间排序。

### 3.4 预警处置（闭环上报）

| 项目 | 内容 |
|------|------|
| 接口名称 | 预警处置（闭环上报） |
| 请求方法 | POST |
| 请求路径 | `/api/v1/warnings/{id}/dispose` |
| 接口描述 | 上报某一处置阶段（护士确认/医生到床/干预完成），推进处置闭环；「预警触发」阶段由系统生成 |
| 前端调用时机 | 详情面板选择「护士确认 / 医生到床 / 干预完成」并填写意见后提交 |
| 前端渲染对应 | 闭环漏斗计数刷新、详情时间线追加 |

**Path 参数：** `id`（预警主键 `warnings.id` 或 `warningNo`）。

**Body 参数：**

| 字段名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| stage | String | 是 | 处置阶段 | 护士确认 / 医生到床 / 干预完成 |
| note | String | 否 | 处置意见 | 已通知管床医生 |
| actorId | String | 是 | 操作人 ID | weiyuan-icu-nurse |
| actorName | String | 是 | 操作人姓名 | 李护士 |
| nextStatus | String | 否 | 阶段完成后的预警状态（缺省按阶段自动推断） | treating |

**请求示例：**

```http
POST /api/v1/warnings/WARN-20261012-001/dispose HTTP/1.1
Authorization: Bearer {token}
Content-Type: application/json

{
  "stage": "护士确认",
  "note": "已确认并通知管床医生",
  "actorId": "weiyuan-icu-nurse",
  "actorName": "李护士",
  "nextStatus": "treating"
}
```

**响应示例（成功）：**

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "warningNo": "WARN-20261012-001",
    "stage": "护士确认",
    "status": "treating",
    "statusLabel": "处置中",
    "actedAt": "2026-10-12T15:02:00+08:00",
    "closedLoopPercent": 86
  }
}
```

**错误码：**

| code | 含义 |
|------|------|
| 200 | 成功 |
| 400 | 参数校验失败（如 stage 非法、预警已闭环重复上报） |
| 401 | 未认证 |
| 404 | 预警不存在 |

## 5. 交互与边界说明

- **闭环阶段顺序**：`预警触发 → 护士确认 → 医生到床 → 干预完成` 为单向推进；后端校验上报阶段不早于当前最新阶段（允许跳过，不允许回退）。
- **闭环率口径**：`closedLoopPercent = 干预完成数 / 预警触发数`（示例汇总为 86%）；24h 计数由 `warning_closed_loop` 按 `stat_date` 落库，由汇总接口聚合。
- **「预警触发」来源**：由预警引擎（NEWS 规则 / LIS 危急值 / 用药/凝血规则）自动生成一条 `stage=预警触发` 记录，前端不提交该阶段。
- **幂等**：处置上报按 `(warning_id, stage)` 去重；重复提交同一阶段返回 400 或覆盖原记录（后端二选一并注释）。
- **危急值接入**：危急值明细当前无 Mock，字段为规范设计；接入 LIS 前 `critical-values` 接口可返回空列表（`total=0`），不阻塞前端。
- **软删除**：预警主表不软删除（保留追溯）；危急值表如需撤单可加 `deleted_at`。

## 6. 前端对接注意事项

- **轮询**：列表/详情建议 30s 轮询刷新 `updatedAt` 与 `activeCount`；避免高频轮询压力。
- **筛选联动**：类别/等级/状态为字典下拉，值取 §4 枚举（英文码），展示用 `*Label` 字段，勿在前端硬编码中文映射。
- **闭环下钻**：漏斗点击阶段 → 调 `closed-loop?stage=护士确认` 拉取该阶段明细；`stages` 用于漏斗渲染，`list` 用于明细表。
- **处置提交**：提交后前端本地更新状态并重新拉取摘要闭环率；`resolved`/`干预完成` 后按钮置灰。
- **危急值标签页**：`total=0` 时展示空状态「暂无危急值」，不报错。
- **字段映射**：所有返回字段为小驼峰（`warningNo`/`patientLabel`/`occurredAt`），与 DDL 蛇形字段对应关系见 §2 各映射表。
