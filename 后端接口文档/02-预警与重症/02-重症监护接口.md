# 02 · 重症监护接口

## 1. 模块概述

| 项 | 内容 |
|----|------|
| 页面名称 | 重症监护（`/#/critical`） |
| 核心功能 | ICU 床位态势、远程查房、床旁体征实时监测、智能预警 |
| 涉及实体 | ICU 床位（icu_bed）、查房会话（ward_round）、查房记录（ward_round_note）、床旁体征（patient_vital）、智能预警（复用 warnings） |
| 数据源 | `public/scenario.json`（`state.beds`、顶层 `measurements`/`trends`）、`public/api/warning-demo.json` |

对应路由（`routes/meta.ts`）：`/critical` modules = `['ICU 床位', '远程查房', '床旁体征', '智能预警']`。

> 说明：ICU 床位、床旁体征、智能预警字段来自 `scenario.json` 真实 Mock（`state.beds`、顶层 `measurements`）；**远程查房（查房会话/查房记录）无 Mock，字段为规范设计**，已在文中标注。

## 2. 数据模型定义

### 2.1 ICU 床位表 `icu_beds`

| 前端展示 | 数据库字段 | 类型 | 必填 | 示例 | 说明 |
|---------|-----------|------|------|------|------|
| 床位编号 | bed_id | String | 是 | `weiyuan-icu-1` | 全局唯一床位 ID |
| 床号 | label | String | 是 | `1床` | 科室内展示床号 |
| 机构/科室 | institution_id / department_id | String | 是 | `weiyuan` / `icu` | 所属机构与 ICU 科室 |
| 占用状态 | status | String | 是 | `occupied` | 见 4.1 床位状态 |
| 患者 | patient_id / patient_name | String | 否 | `DEMO-001` / `演示患者01` | 占用患者（冗余姓名） |
| 危重程度 | severity | String | 否 | `critical` | 见 4.2 危重程度 |
| 监护仪 | monitor_id | String | 否 | `MON-ICU-01` | 绑定床旁监护设备 |
| 入科时间 | admitted_at | DateTime | 否 | `2026-10-11T09:30:00+08:00` | 患者入科时间 |

```sql
CREATE TABLE `icu_beds` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `bed_id` VARCHAR(32) NOT NULL COMMENT '床位ID，如 weiyuan-icu-1',
  `label` VARCHAR(16) NOT NULL DEFAULT '' COMMENT '床号，如 1床',
  `institution_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '机构ID',
  `department_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '科室ID，如 icu',
  `status` VARCHAR(16) NOT NULL DEFAULT 'available' COMMENT '状态：available空闲/occupied占用',
  `patient_id` VARCHAR(32) NULL DEFAULT NULL COMMENT '占用患者ID',
  `patient_name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '患者姓名冗余',
  `severity` VARCHAR(16) NOT NULL DEFAULT '' COMMENT '危重程度：critical/acute/general',
  `monitor_id` VARCHAR(32) NULL DEFAULT NULL COMMENT '绑定床旁监护设备ID',
  `admitted_at` DATETIME NULL DEFAULT NULL COMMENT '入科时间',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_bed_id` (`bed_id`),
  KEY `idx_dept_status` (`department_id`, `status`),
  KEY `idx_patient` (`patient_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='ICU床位表';
```

索引说明：
- `uk_bed_id`：床位编号全局唯一。
- `idx_dept_status`：ICU 床位态势按科室 + 占用状态聚合（总床/占用/空床）。
- `idx_patient`：患者 ↔ 床位反查。

### 2.2 床旁体征表 `patient_vitals`

> 字段对齐 `scenario.json` 顶层 `measurements`（实时/时序共用一张表）。

| 前端展示 | 数据库字段 | 类型 | 必填 | 示例 | 说明 |
|---------|-----------|------|------|------|------|
| 患者 | patient_id | String | 是 | `DEMO-001` | 关联患者 ID |
| 心率 | heart_rate | Integer | 是 | `86` | 次/分 |
| 血氧 | spo2 | Integer | 是 | `94` | % |
| 呼吸率 | resp | Integer | 是 | `18` | 次/分 |
| 体温 | temp | Decimal(3,1) | 是 | `36.5` | ℃ |
| 收缩压/舒张压 | systolic / diastolic | Integer | 是 | `110` / `65` | mmHg |
| NEWS 评分 | news | Integer | 否 | `6` | 早期预警评分 |
| 采集时间 | measured_at | DateTime | 是 | `2026-10-12T14:58:00+08:00` | 采集时间 |
| 来源 | source | String | 否 | `device` | device 设备/manual 手工 |

```sql
CREATE TABLE `patient_vitals` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `patient_id` VARCHAR(32) NOT NULL COMMENT '患者ID',
  `heart_rate` SMALLINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '心率 次/分',
  `spo2` SMALLINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '血氧 %',
  `resp` SMALLINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '呼吸率 次/分',
  `temp` DECIMAL(3,1) NOT NULL DEFAULT 0 COMMENT '体温 ℃',
  `systolic` SMALLINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '收缩压 mmHg',
  `diastolic` SMALLINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '舒张压 mmHg',
  `news` SMALLINT UNSIGNED NULL DEFAULT NULL COMMENT 'NEWS 早期预警评分',
  `source` VARCHAR(16) NOT NULL DEFAULT 'device' COMMENT '来源：device设备/manual手工',
  `measured_at` DATETIME NOT NULL COMMENT '采集时间',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  PRIMARY KEY (`id`),
  KEY `idx_patient_measured` (`patient_id`, `measured_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='床旁体征表';
```

索引说明：
- `idx_patient_measured`：实时体征取「每患者最新一条」与体征时序曲线按时间窗拉取，均命中该联合索引。

### 2.3 查房会话表 `ward_rounds`（远程查房 · 字段为规范设计）

| 前端展示 | 数据库字段 | 类型 | 必填 | 示例 | 说明 |
|---------|-----------|------|------|------|------|
| 查房编号 | round_id | String | 是 | `WR-20261012-01` | 唯一编号 |
| 病房/床位 | ward_id / ward_label | String | 是 | `weiyuan-icu-5` / `ICU 5床` | 查房对象 |
| 机构/科室 | institution_id / department_id | String | 是 | `weiyuan` / `icu` | 所属科室 |
| 患者 | patient_id / patient_label | String | 否 | `DEMO-005` / `ICU 5床` | 关联患者 |
| 主题 | title | String | 是 | `ICU 5床 早查房` | 查房主题 |
| 主持医生 | doctor_id / doctor_name | String | 是 | `weiyuan-icu-doctor` / `张医生` | 主持医生 |
| 参与人 | participants | String | 否 | `李护士 / 平台会诊` | 参与人（逗号分隔） |
| 状态 | status | String | 是 | `scheduled` | 见 4.3 查房状态 |
| 计划/开始/结束 | planned_at / started_at / finished_at | DateTime | 是/否 | `2026-10-12T08:00:00+08:00` | 查房时间线 |
| 小结 | summary | String | 否 | `生命体征平稳，调整用药` | 查房小结 |

```sql
CREATE TABLE `ward_rounds` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `round_id` VARCHAR(32) NOT NULL COMMENT '查房编号，如 WR-20261012-01',
  `ward_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '病房/床位ID',
  `ward_label` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '床位标签，如 ICU 5床',
  `institution_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '机构ID',
  `department_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '科室ID',
  `patient_id` VARCHAR(32) NULL DEFAULT NULL COMMENT '患者ID',
  `patient_label` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '患者标签冗余',
  `title` VARCHAR(128) NOT NULL DEFAULT '' COMMENT '查房主题',
  `doctor_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '主持医生ID',
  `doctor_name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '主持医生姓名',
  `participants` VARCHAR(255) NOT NULL DEFAULT '' COMMENT '参与人，逗号分隔',
  `status` VARCHAR(16) NOT NULL DEFAULT 'scheduled' COMMENT '状态：scheduled/in_progress/finished',
  `planned_at` DATETIME NOT NULL COMMENT '计划查房时间',
  `started_at` DATETIME NULL DEFAULT NULL COMMENT '实际开始时间',
  `finished_at` DATETIME NULL DEFAULT NULL COMMENT '实际结束时间',
  `summary` VARCHAR(255) NOT NULL DEFAULT '' COMMENT '查房小结',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_round_id` (`round_id`),
  KEY `idx_dept_status_planned` (`department_id`, `status`, `planned_at`),
  KEY `idx_patient` (`patient_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='远程查房会话表';
```

索引说明：
- `uk_round_id`：查房编号唯一。
- `idx_dept_status_planned`：查房列表按科室 + 状态 + 计划时间排序。
- `idx_patient`：患者维度反查历史查房。

### 2.4 查房记录表 `ward_round_notes`（字段为规范设计）

| 前端展示 | 数据库字段 | 类型 | 必填 | 示例 | 说明 |

CREATE TABLE `ward_round_notes` (

索引说明：
- `idx_round`：查房详情回读其下全部记录。

### 3.5 获取患者体征时序

| 项目 | 内容 |
|------|------|
| 接口名称 | 获取患者体征时序 |
| 请求方法 | GET |
| 请求路径 | `/api/v1/critical/patients/{id}/vitals` |
| 接口描述 | 返回指定患者在一段时间窗内的连续体征序列（时序曲线） |
| 前端调用时机 | 点击床位/患者进入体征趋势图 |
| 前端渲染对应 | 体征时序折线图（心率/血氧/呼吸/血压/体温/NEWS） |

**Path 参数：** `id`（患者 ID，如 `DEMO-001`）。

**Query 参数：**

| 字段名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| hours | Integer | 否 | 回看小时数（缺省 24，最大 72） | 24 |
| startAt | String | 否 | 起时间（ISO 8601） | 2026-10-12T00:00:00+08:00 |
| endAt | String | 否 | 止时间 | 2026-10-12T23:59:59+08:00 |

> 说明：`hours` 与 `startAt/endAt` 二选一，均缺省回看近 24h。

**请求示例：**

```http
GET /api/v1/critical/patients/DEMO-001/vitals?hours=24 HTTP/1.1
Authorization: Bearer {token}
```

**响应示例（成功）：**

## 5. 交互与边界说明

- **体征实时 vs 时序**：同一张 `patient_vitals` 支撑两个读场景——「实时」取每患者 `measured_at` 最新一条，「时序」按时间窗连续拉取；高写入量建议按月分表或接入时序库。
- **预警阈值判定**：`alert` 与 `newsLabel` 由后端基于规则实时计算（news ≥ 5 / SpO₂ < 93 / 心率 > 100），不在前端硬编码。
- **智能预警复用**：`/critical/alerts` 是预警中心 `warnings` 的 ICU 子集查询，联动不新建表。
- **查房状态流转**：`scheduled → in_progress → finished` 单向；`started_at`/`finished_at` 由医生端操作回填（演示阶段可缺省）。
- **体征无患者**：空床不产生体征，`vitals` 只返回占用床位患者；床位与体征按 `patient_id` 关联，床位表患者冗余名需与实数据同步。
- **无 Mock 字段合规**：远程查房（`ward_rounds`/`ward_round_notes`）与查房记录接口为规范设计，后端可先落空表，前端展示空状态。

## 6. 前端对接注意事项

- **轮询策略**：床旁体征 10s 轮询（仅拉 `updatedAt` 与最新一条），床位态势 30s 轮询；停止页面即停止计时器。
- **趋势图**：体征时序接口返回 `series` 已按 `at` 升序，前端直接映射折线，无需二次排序；跨 24h 建议下采样。
- **空状态**：无菌床位/无查房/无体征时返回 `total=0`，前端显示空状态文案，不报错。
- **字段映射**：返回小驼峰（`bedId`/`patientId`/`heartRate`/`measuredAt`），DDL 蛇形对应见 §2 映射表。
- **枚举展示**：`statusLabel`/`severityLabel`/`newsLabel` 由后端下发，前端不维护中文字典。
- **权限**：查房意见写入需 `roleView` 为医生或护士角色，后端校验 `actorId` 匹配当前 token。
