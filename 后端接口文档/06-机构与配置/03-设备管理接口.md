# 03 · 设备管理接口

## 1. 模块概述

| 项 | 内容 |
|----|------|
| 页面名称 | 设备管理（`/#/devices`）、会诊门户设备绑定（`meeting-portal.html#devices`） |
| 核心功能 | 监护设备台账、床位绑定/改绑/解绑、设备巡检记录 |
| 涉及实体 | 医疗设备（medical_device） |
| 数据源 | `public/api/device-bindings.json`；患者/床位关联见 `public/scenario.json` |

对应路由（`routes/meta.ts`）：`/devices`（监护设备、床位绑定、巡检）。

---

## 2. 数据模型定义

### 2.1 医疗设备表 `medical_devices`

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |
|---------|-----------|------|------|------|
| 设备 | device_id / name | String | 是 | 设备编号与名称（监护仪/输液泵） |
| 绑定床位 | bed_id / bed_label | String | 否 | 绑定床位 |
| 关联患者 | patient_id / patient_name | String | 否 | 关联患者 |
| 在线 | online | Boolean | 是 | 设备在线状态 |
| 告警 | alarm | Boolean | 是 | 参数告警 |
| 绑定时间 | bound_at | DateTime | 否 | 绑定时间 |
| 原床位 | previous_bed_id | String | 否 | 改绑前床位 |
| 解绑时间 | unbound_at | DateTime | 否 | 解绑时间 |

```sql
CREATE TABLE `medical_devices` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `device_id` VARCHAR(64) NOT NULL COMMENT '设备编号，如 MON-weiyuan-icu-1',
  `name` VARCHAR(32) NOT NULL DEFAULT '监护仪' COMMENT '设备名称',
  `bed_id` VARCHAR(64) NULL DEFAULT NULL COMMENT '绑定床位编号',
  `bed_label` VARCHAR(64) NULL DEFAULT NULL COMMENT '绑定床位标签',
  `patient_id` VARCHAR(64) NULL DEFAULT NULL COMMENT '关联患者编号',
  `patient_name` VARCHAR(64) NULL DEFAULT NULL COMMENT '关联患者姓名',
  `online` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '在线：0离线1在线',
  `alarm` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '告警：0无1告警',
  `bound_at` DATETIME NULL DEFAULT NULL COMMENT '绑定时间',
  `previous_bed_id` VARCHAR(64) NULL DEFAULT NULL COMMENT '改绑前床位编号',
  `unbound_at` DATETIME NULL DEFAULT NULL COMMENT '解绑时间',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_device_id` (`device_id`),
  KEY `idx_bed` (`bed_id`),
  KEY `idx_online_alarm` (`online`, `alarm`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='医疗设备表';
```

## 3. 接口清单

### 3.1 获取设备台账与床位列表

| 项目 | 内容 |
|------|------|
| 接口名称 | 获取设备台账与床位列表 |
| 请求方法 | GET |
| 请求路径 | `/api/v1/devices` |
| 接口描述 | 返回设备台账（含绑定/在线/告警）与可选绑定床位列表 |
| 前端调用时机 | `#devices` 页加载时 |
| 前端渲染对应 | 设备绑定表格、绑定下拉框 |

**Query 参数：** `ward`（String，可选，按病区筛选）。

**响应示例（成功）：**

```json

  "message": "success",
  "data": {

    "notice": "演示设备台账 · 与 bed 号对齐",
    "devices": [
      {
        "deviceId": "MON-weiyuan-icu-1",
        "name": "监护仪",
        "bedId": "weiyuan-icu-1",
        "bedLabel": "ICU 1床",
        "patientId": "DEMO-001",
        "patientName": "演示患者01",
        "online": true,

        "previousBedId": null,
        "unboundAt": null

    ],
    "beds": [
      { "bedId": "weiyuan-icu-1", "label": "ICU 1床", "ward": "icu" }
    ]
  }
}
```

**错误码：** 200 / 401。

### 3.2 设备改绑/解绑床位

| 项目 | 内容 |
|------|------|
| 接口名称 | 设备改绑/解绑床位 |
| 请求方法 | PUT |
| 请求路径 | `/api/v1/devices/{deviceId}/binding` |
| 接口描述 | 将设备绑定到床位；`bedId` 为空表示解绑 |
| 前端调用时机 | 设备行内「改绑」下拉框变更时 |
| 前端渲染对应 | 设备绑定表格实时更新 |

**Path 参数：** `deviceId`（String）。

**Body 参数：**

| 字段名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| bedId | String | 否 | 目标床位编号，空串表示解绑 | weiyuan-icu-1 |
| bedLabel | String | 否 | 床位标签 | ICU 1床 |

**请求示例：**

```http
PUT /api/v1/devices/MON-weiyuan-icu-1/binding HTTP/1.1
Authorization: Bearer {token}
Content-Type: application/json

{ "bedId": "weiyuan-icu-3", "bedLabel": "ICU 3床" }
```

**响应示例（成功）：**

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "deviceId": "MON-weiyuan-icu-1",
    "bedId": "weiyuan-icu-3",
    "bedLabel": "ICU 3床",
    "previousBedId": "weiyuan-icu-1",
    "boundAt": "2026-10-13T09:40:00+08:00"
  }
}
```

**错误码：** 200 / 400（床位不存在）/ 401 / 404（设备不存在）。

> 说明：新增 / 更新设备、设备巡检记录等剩余接口见《接口清单总表》第 15 节（设备管理，共 5 接口），已并入本文件后续章节。

## 4. 数据模型补充

### 4.1 设备巡检记录表 `device_inspections`

> 设备巡检记录前端无独立 Mock JSON，字段依据 `meta.ts`（`/devices` 模块「巡检」）与设备管理业务域推导，**字段为规范设计**。

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |
|---------|-----------|------|------|------|
| 巡检编号 | inspection_id | String | 是 | 巡检记录编号 |
| 设备 | device_id | String | 是 | 关联 medical_devices.device_id |
| 巡检项 | item | String | 是 | 巡检项（电源/管路/参数标定） |
| 结果 | result | String | 是 | ok/fault |
| 巡检人 | inspector | String | 是 | 巡检人 |
| 巡检时间 | check_at | DateTime | 是 | 巡检时间 |
| 备注 | note | String | 否 | 巡检说明 |

```sql
CREATE TABLE `device_inspections` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `inspection_id` VARCHAR(64) NOT NULL COMMENT '巡检记录编号',
  `device_id` VARCHAR(64) NOT NULL COMMENT '设备编号',
  `item` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '巡检项：电源/管路/参数标定/报警测试',
  `result` VARCHAR(16) NOT NULL DEFAULT 'ok' COMMENT '结果：ok正常/fault异常',
  `inspector` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '巡检人',
  `check_at` DATETIME NOT NULL COMMENT '巡检时间',
  `note` VARCHAR(255) NOT NULL DEFAULT '' COMMENT '巡检说明',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_inspection_id` (`inspection_id`),
  KEY `idx_device_check` (`device_id`, `check_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='设备巡检记录表';
```

索引说明：`idx_device_check` 支撑「按设备查历史巡检」与巡检看板按时间倒序。

## 5. 接口清单（续）

### 5.1 新增设备

| 项目 | 内容 |
|------|------|
| 接口名称 | 新增设备 |
| 请求方法 | POST |
| 请求路径 | `/api/v1/devices` |
| 接口描述 | 维护设备：新增一台床旁监护设备（可选附带绑定床位） |
| 前端调用时机 | 设备台账「新增设备」 |
| 前端渲染对应 | 设备表格新增行 |

**Body 参数：**

| 字段名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| deviceId | String | 是 | 设备编号 | MON-weiyuan-icu-6 |
| name | String | 是 | 设备名称 | 监护仪 |
| bedId | String | 否 | 绑定床位编号（可空） | weiyuan-emergency-1 |
| bedLabel | String | 否 | 绑定床位标签 | 急诊 1床 |
| patientId | String | 否 | 关联患者编号 | DEMO-005 |
| patientName | String | 否 | 关联患者姓名 | 演示患者05 |
| online | Boolean | 否 | 在线状态（缺省 false） | false |
| alarm | Boolean | 否 | 告警状态（缺省 false） | false |

**请求示例：**

```http
POST /api/v1/devices HTTP/1.1
Authorization: Bearer {token}
Content-Type: application/json

{
  "deviceId": "MON-weiyuan-icu-6",
  "name": "监护仪",
  "bedId": "weiyuan-icu-6",
  "bedLabel": "ICU 6床",
  "online": false,
  "alarm": false
}
```

**响应示例（成功）：**

```json
{ "code": 200, "message": "success", "data": { "deviceId": "MON-weiyuan-icu-6" } }
```

**错误码：**

| code | 含义 |
|------|------|
| 200 | 成功 |
| 400 | 参数校验失败（deviceId/name 为空） |
| 401 | 未认证 |
| 409 | 设备编号已存在 |

### 5.2 更新设备

| 项目 | 内容 |
|------|------|
| 接口名称 | 更新设备 |
| 请求方法 | PUT |
| 请求路径 | `/api/v1/devices/{id}` |
| 接口描述 | 维护设备：更新设备名称、在线/告警状态（床位绑定走改绑接口） |
| 前端调用时机 | 设备台账「编辑」 |
| 前端渲染对应 | 设备行内更新 |

**Path 参数：** `id`（String，设备编号，如 `MON-weiyuan-icu-1`）。

**Body 参数：** `name/online/alarm/bedId/bedLabel/patientId/patientName`（全部可选，只更新传入字段；床位变更建议走 §3.2 改绑接口以保留历史）。

**响应示例（成功）：**

```json
{ "code": 200, "message": "success", "data": { "deviceId": "MON-weiyuan-icu-1" } }
```

**错误码：** 200 / 400 / 401 / 404（设备不存在）。

## 6. 枚举说明

### 6.1 巡检结果 `result`

| code | label |
|------|-------|
| `ok` | 正常 |
| `fault` | 异常 |

> 设备绑定历史（`previous_bed_id` / `unbound_at`）与在线/告警状态沿用 §2.1 `medical_devices` 定义；改绑/解绑走 §3.2 `PUT /api/v1/devices/{deviceId}/binding`，与新增/更新解耦，保证绑定轨迹可追溯。
