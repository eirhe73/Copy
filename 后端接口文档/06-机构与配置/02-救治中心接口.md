# 02 · 救治中心接口

## 1. 模块概述

| 项 | 内容 |
|----|------|
| 页面名称 | 救治中心（`/#/centers`，导航标题「五大中心」） |
| 核心功能 | 五大中心列表、中心能力画像、画像维护 |
| 涉及实体 | 救治中心（care_center）、能力画像（care_center_profile） |
| 数据源 | 前端常量 `mU`：胸痛中心、卒中中心、创伤中心、危重孕产妇救治中心、危重新生儿救治中心；患者归属中心见 `scenario.json`（`centers` 映射） |

对应路由（`routes/meta.ts`）：`/centers`（五大中心、能力画像）。前端为「科室协作 · 通用入口」：顶部中心 Tab，中部指标卡（中心可见患者、待转诊等），底部为各病种救治路径/时限考核说明。

> 说明：五大中心名称、Tab、指标卡为前端真实结构；中心能力画像字段无独立 Mock，**字段为规范设计**，依据 `meta.ts` 模块描述 + 五大中心业务语义推导。

## 2. 数据模型定义

### 2.1 救治中心表 `care_centers`

| 前端展示 | 数据库字段 | 类型 | 必填 | 示例 | 说明 |
|---------|-----------|------|------|------|------|
| 中心编号 | center_id | String | 是 | `chest-pain` | 唯一编号 |
| 中心名 | name | String | 是 | `胸痛中心` | 五大中心名 |
| 牵头科室 | lead_dept | String | 是 | `cardiology` | 牵头科室编码 |
| 协作科室 | related_depts | JSON | 否 | `["emergency","radiology"]` | 协作科室 |
| 状态 | status | String | 是 | `active` | active/inactive |
| 排序 | sort | Int | 否 | 1 | 五大中心固定顺序 |

```sql
CREATE TABLE `care_centers` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `center_id` VARCHAR(32) NOT NULL COMMENT '中心编号，如 chest-pain',
  `name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '中心名称，如 胸痛中心',
  `lead_dept` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '牵头科室编码',
  `related_depts` JSON NULL COMMENT '协作科室编码数组',
  `status` VARCHAR(16) NOT NULL DEFAULT 'active' COMMENT '状态：active/inactive',
  `sort` INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '排序',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_center_id` (`center_id`),
  KEY `idx_status_sort` (`status`, `sort`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='救治中心表';
```

### 2.2 中心能力画像表 `care_center_profiles`

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |
|---------|-----------|------|------|------|
| 中心 | center_id | String | 是 | 关联 care_centers |
| 机构 | org_id | String | 是 | 承载机构 |
| 可见患者 | visible_patients | Int | 是 | 中心可见患者数 |
| 待转诊 | pending_transfer | Int | 是 | 待转诊数 |
| 团队人数 | team_size | Int | 否 | 救治团队人数 |
| 关键设备 | equipment | JSON | 否 | 设备清单（DSA/CT/ECMO 等） |
| 年救治量 | annual_volume | Int | 否 | 年救治病例数 |
| 达标率 | pathway_rate | Decimal(5,4) | 否 | 路径达标率 0~1 |
| 时限考核 | assessment_note | String | 否 | 考核配置说明 |
| 画像更新时间 | profiled_at | DateTime | 是 | 画像更新时间 |

```sql
CREATE TABLE `care_center_profiles` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `center_id` VARCHAR(32) NOT NULL COMMENT '中心编号',
  `org_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '承载机构编码',
  `visible_patients` INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '中心可见患者数',
  `pending_transfer` INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '待转诊数',
  `team_size` INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '救治团队人数',
  `equipment` JSON NULL COMMENT '关键设备清单数组',
  `annual_volume` INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '年救治病例数',
  `pathway_rate` DECIMAL(5,4) NOT NULL DEFAULT 0 COMMENT '路径达标率 0~1',
  `assessment_note` VARCHAR(255) NOT NULL DEFAULT '' COMMENT '时限考核配置说明',
  `profiled_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '画像更新时间',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_center_org` (`center_id`, `org_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='中心能力画像表';
```

索引说明：`uk_center_org` 保证「中心 × 机构」一只一份能力画像；画像随机构切换按此键查询。

## 3. 接口清单

### 3.1 获取五大中心列表

| 项目 | 内容 |
|------|------|
| 接口名称 | 获取五大中心列表 |
| 请求方法 | GET |
| 请求路径 | `/api/v1/centers` |
| 接口描述 | 返回五大中心目录（胸痛/卒中/创伤/危重孕产妇/危重新生儿），含各中心可见患者与待转诊概览 |
| 前端调用时机 | `/#/centers` 页加载 |
| 前端渲染对应 | 中心 Tab、指标卡（中心可见患者 / 待转诊） |

**Query 参数：** `orgId`（String，可选，按机构过滤中心画像）。

```json
      },
      {
        "centerId": "stroke",
        "name": "卒中中心",
```

### 3.2 获取中心能力画像

| 项目 | 内容 |
|------|------|
| 接口名称 | 获取中心能力画像 |
| 请求方法 | GET |
| 请求路径 | `/api/v1/centers/{id}/profile` |
| 接口描述 | 返回单个中心的能力画像：团队、设备、年量、路径达标率、时限考核配置 |
| 前端调用时机 | 选中中心 Tab 查看画像 |
| 前端渲染对应 | 中心能力指标卡、协作科室、时限考核说明 |

**Path 参数：** `id`（String，中心编号，如 `chest-pain`）。

**Query 参数：** `orgId`（String，可选，默认当前机构）。

```json
    "orgName": "威远县人民医院",

    "relatedDepts": ["emergency", "radiology"],
    "visiblePatients": 6,
    "pendingTransfer": 2,

    "equipment": ["DSA", "CT", "床旁肌钙蛋白检测"],

```

**错误码：** 200 / 401 / 404（中心不存在）。

### 3.3 更新中心能力画像

| 项目 | 内容 |
|------|------|
| 接口名称 | 更新中心能力画像 |
| 请求方法 | PUT |
| 请求路径 | `/api/v1/centers/{id}/profile` |
| 接口描述 | 维护中心能力画像：团队人数、关键设备、年救治量、路径达标率、时限考核配置 |
| 前端调用时机 | 中心画像「编辑能力」保存 |
| 前端渲染对应 | 画像即时刷新 |

**Path 参数：** `id`（String，中心编号）。

**Body 参数：**

| 字段名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| orgId | String | 是 | 承载机构编码 | weiyuan |
| teamSize | Integer | 否 | 救治团队人数 | 12 |
| equipment | Array | 否 | 关键设备清单 | ["DSA","CT"] |
| annualVolume | Integer | 否 | 年救治病例数 | 328 |
| pathwayRate | Number | 否 | 路径达标率（0~1） | 0.92 |
| assessmentNote | String | 否 | 时限考核配置说明 | 已配置：D2B ≤ 90 分钟 |

**请求示例：**

```http
PUT /api/v1/centers/chest-pain/profile HTTP/1.1
Authorization: Bearer {token}
Content-Type: application/json

{
  "orgId": "weiyuan",
  "teamSize": 13,
  "equipment": ["DSA", "CT", "床旁肌钙蛋白检测"],
  "annualVolume": 340,
  "pathwayRate": 0.94,
  "assessmentNote": "已配置：D2B ≤ 90 分钟"
}
```

**响应示例（成功）：**

```json
{ "code": 200, "message": "success", "data": { "centerId": "chest-pain", "orgId": "weiyuan", "profiledAt": "2026-10-13T10:00:00+08:00" } }
```

**错误码：** 200 / 400（机构不存在）/ 401 / 404（中心不存在）。

## 4. 枚举与边界说明

### 4.1 五大中心目录

| center_id | name | 牵头科室 |
|-----------|------|---------|
| `chest-pain` | 胸痛中心 | 心脏内科（cardiology） |
| `stroke` | 卒中中心 | 神经内科（neurology） |
| `trauma` | 创伤中心 | 创伤医学中心（trauma） |
| `maternal` | 危重孕产妇救治中心 | 妇产科（obstetrics） |
| `neonatal` | 危重新生儿救治中心 | 儿科（pediatrics） |

### 4.2 边界说明

- **患者归属**：患者通过 `assignCenter`（`scenario.json` 中的中心映射）归入某中心；「中心可见患者」为该映射下的患者数，「待转诊」为关联转诊待接收数，均由服务端聚合实时计算，不落库为静态值。
- **协作入口**：五大中心为「科室协作 · 通用入口」，一个中心关联多个协作科室（`related_depts`）；列表只返回目录与概览，画像按 `orgId` 区分各机构能力。
- **时限考核**：演示阶段 `assessmentNote` 默认为「尚未配置机构考核标准，不推定超时结论」，配置后由质控路径达标率（`pathway_rate`）承接，避免未配置标准时误报超时。
