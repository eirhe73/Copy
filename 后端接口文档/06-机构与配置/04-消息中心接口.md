# 04 · 消息中心接口

## 1. 模块概述

| 项 | 内容 |
|----|------|
| 页面名称 | 消息中心（`/#/messages`，导航标题「通知」） |
| 核心功能 | 站内消息、服务通知、待办提醒（站内待办 P0 闭环 + 微信/短信可插拔触达通道） |
| 涉及实体 | 站内消息（message）、服务通知（notification）、待办（todo） |
| 数据源 | 前端首页消息层（`mini-layer`）：站内待办「需要我处理」、微信服务通知；`scenario.json` 事件/预警驱动生成 |

对应路由（`routes/meta.ts`）：`/messages`（服务通知、待办提醒）。前端消息语义：**站内待办为 P0 闭环**（不依赖微信也能闭环），微信/短信为可插拔的外部触达通道，通道失败不影响任务流转。

> 说明：消息中心无独立 Mock JSON，字段依据前端消息层渲染结构（`title/text/read/at/patientName` 与 `title/hint/tone/go`）+ 消息业务域推导，**字段为规范设计**。

## 2. 数据模型定义

### 2.1 站内消息表 `messages`

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |
|---------|-----------|------|------|------|
| 消息 | message_id | String | 是 | 消息编号 |
| 标题 | title | String | 是 | 消息标题 |
| 内容 | text | String | 否 | 消息正文 |
| 已读 | is_read | Boolean | 是 | 0未读/1已读 |
| 关联患者 | patient_id / patient_name | String | 否 | 关联患者 |
| 分类 | category | String | 是 | alert/consult/transfer |
| 跳转 | link | String | 否 | 前端跳转路径 |
| 时间 | at | DateTime | 是 | 消息时间 |

```sql
CREATE TABLE `messages` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `message_id` VARCHAR(64) NOT NULL COMMENT '消息编号',
  `title` VARCHAR(128) NOT NULL DEFAULT '' COMMENT '消息标题',
  `text` VARCHAR(500) NOT NULL DEFAULT '' COMMENT '消息正文',
  `is_read` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '是否已读：0否1是',
  `patient_id` VARCHAR(64) NULL DEFAULT NULL COMMENT '关联患者编号',
  `patient_name` VARCHAR(64) NULL DEFAULT NULL COMMENT '关联患者姓名',
  `category` VARCHAR(16) NOT NULL DEFAULT '' COMMENT '分类：alert/consult/transfer',
  `link` VARCHAR(255) NOT NULL DEFAULT '' COMMENT '前端跳转路径',
  `at` DATETIME NOT NULL COMMENT '消息时间',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_message_id` (`message_id`),
  KEY `idx_read_at` (`is_read`, `at`),
  KEY `idx_patient` (`patient_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='站内消息表';
```

### 2.2 服务通知表 `notifications`

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |
|---------|-----------|------|------|------|
| 通知 | notification_id | String | 是 | 通知编号 |
| 标题 | title | String | 是 | 通知标题 |
| 内容 | text | String | 否 | 通知内容 |
| 已读 | is_read | Boolean | 是 | 0未读/1已读 |
| 患者 | patient_name | String | 否 | 关联患者姓名 |
| 触达通道 | channel | String | 是 | wechat/sms |
| 会诊令牌 | token | String | 否 | 会诊入会令牌 |
| 时间 | at | DateTime | 是 | 通知时间 |

```sql
CREATE TABLE `notifications` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `notification_id` VARCHAR(64) NOT NULL COMMENT '通知编号',
  `title` VARCHAR(128) NOT NULL DEFAULT '' COMMENT '通知标题',
  `text` VARCHAR(500) NOT NULL DEFAULT '' COMMENT '通知内容',
  `is_read` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '是否已读：0否1是',
  `patient_name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '关联患者姓名',
  `channel` VARCHAR(16) NOT NULL DEFAULT 'wechat' COMMENT '触达通道：wechat微信/sms短信',
  `token` VARCHAR(128) NULL DEFAULT NULL COMMENT '会诊入会令牌',
  `at` DATETIME NOT NULL COMMENT '通知时间',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_notification_id` (`notification_id`),
  KEY `idx_channel_read` (`channel`, `is_read`),
  KEY `idx_at` (`at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='服务通知表';
```

### 2.3 待办表 `todos`

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |
|---------|-----------|------|------|------|
| 待办 | todo_id | String | 是 | 待办键（key） |
| 标题 | title | String | 是 | 待办标题 |
| 提示 | hint | String | 否 | 待办提示 |
| 紧急度 | tone | String | 是 | warn/danger/default |
| 跳转 | go | String | 否 | 跳转目标 |
| 优先级 | priority | String | 是 | P0/P1 |
| 状态 | status | String | 是 | open/done |
| 时间 | at | DateTime | 是 | 生成时间 |

```sql
CREATE TABLE `todos` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `todo_id` VARCHAR(64) NOT NULL COMMENT '待办键',
  `title` VARCHAR(128) NOT NULL DEFAULT '' COMMENT '待办标题',
  `hint` VARCHAR(255) NOT NULL DEFAULT '' COMMENT '待办提示',
  `tone` VARCHAR(16) NOT NULL DEFAULT 'warn' COMMENT '紧急度：warn/danger/default',
  `go` VARCHAR(255) NOT NULL DEFAULT '' COMMENT '跳转目标',
  `priority` VARCHAR(8) NOT NULL DEFAULT 'P0' COMMENT '优先级：P0/P1',
  `status` VARCHAR(16) NOT NULL DEFAULT 'open' COMMENT '状态：open/done',
  `at` DATETIME NOT NULL COMMENT '生成时间',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_todo_id` (`todo_id`),
  KEY `idx_priority_status` (`priority`, `status`),
  KEY `idx_at` (`at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='待办提醒表';
```

索引说明：`idx_priority_status` 支撑「待办汇总」按 P0 优先 + 未办排序；`idx_channel_read` / `idx_read_at` 支撑消息中心未读角标。

## 3. 接口清单

### 3.1 获取消息列表

| 项目 | 内容 |
|------|------|
| 接口名称 | 获取站内消息列表 |
| 请求方法 | GET |
| 请求路径 | `/api/v1/messages` |
| 接口描述 | 站内消息分页列表（含未读统计） |
| 前端调用时机 | `/#/messages` 页加载 |
| 前端渲染对应 | 站内消息列表、未读角标 |

**Query 参数：** `category`（可选，分类过滤）、`isRead`（可选，0/1）、`pageNum`/`pageSize`（可选分页）。

    "unread": 3,

    "list": [
      {
        "messageId": "MSG-20261012-001",
        "title": "紧急 · 体征阈值预警",

## 4. 枚举与边界说明

### 4.1 待办紧急度 `tone`

| code | 含义 |
|------|------|
| `danger` | 高危/紧急 |
| `warn` | 需关注 |
| `default` | 普通 |

### 4.2 优先级 `priority`

| code | 含义 |
|------|------|
| `P0` | 站内待办 · 不依赖微信也能闭环 |
| `P1` | 服务通知项 · 可插拔外部触达通道 |

### 4.3 边界说明

- **双通道闭环**：站内待办（P0）为主闭环通道；微信/短信（P1）为可插拔触达通道，通道发送失败不影响任务流转（前端明确「通道失败不影响任务流转」）。
- **待办生成**：待办由业务事件驱动生成——转诊待接收（`step===requested`）、身份待核实、执行待确认等；服务端在事件流转时写入 `todos`。
- **未读口径**：消息/通知的未读角标按 `is_read=0` 计数，前端在列表加载时读未读数并展示「未读」徽标。
