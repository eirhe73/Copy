# 01 · 机构管理接口

## 1. 模块概述

| 项 | 内容 |
|----|------|
| 页面名称 | 机构管理（`/#/organizations`，导航标题「协作机构」） |
| 核心功能 | 医共体成员机构名录、科室结构（科室树）、权限范围、机构成员 |
| 涉及实体 | 机构（organization）、科室（department）、机构成员（organization_member）、机构权限（organization_permission） |
| 数据源 | `src/data/institutions.json`（机构名录：华西/内江一院/威远县/连界镇/船石村五级） |

对应路由（`routes/meta.ts`）：`/organizations`（医共体成员、科室结构、权限范围）。前端机构页左侧为机构层级链（村级→乡镇→县级→市级→中心），右侧为机构详情，Tab 分「公开科室」「公开医护资料」「本科室人员」。

## 2. 数据模型定义

### 2.1 机构表 `organizations`

| 前端展示 | 数据库字段 | 类型 | 必填 | 示例 | 说明 |
|---------|-----------|------|------|------|------|
| 机构 ID | org_id | String | 是 | `weiyuan` | 机构编码（承接 scenario.institutionId） |
| 机构名 | name | String | 是 | `威远县人民医院` | 全称 |
| 简称 | short_name | String | 否 | `威远县医院` | 简称 |
| 层级 | level | String | 是 | `county` | 见 §4 枚举 |
| 层级名 | level_label | String | 是 | `县级医院` | 层级显示 |
| 省 | province | String | 是 | `四川省` | — |
| 市 | city | String | 是 | `内江市` | — |
| 县 | county | String | 否 | `威远县` | — |
| 乡镇 | town | String | 否 | `连界镇` | — |
| 已核实 | verified | Boolean | 是 | `true` | 机构资料是否核实 |
| 现状核实 | current_operation_verified | Boolean | 否 | `false` | 当前执业状态是否核实 |
| 核实说明 | verification_scope | String | 否 | — | 核实范围说明 |
| 依据时间 | evidence_as_of | String | 否 | `2023-12-15` | 证据截至日期 |

```sql
CREATE TABLE `organizations` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `org_id` VARCHAR(32) NOT NULL COMMENT '机构编码，如 weiyuan',
  `name` VARCHAR(128) NOT NULL DEFAULT '' COMMENT '机构全称',
  `short_name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '机构简称',
  `level` VARCHAR(16) NOT NULL DEFAULT 'county' COMMENT '层级：center/city/county/township/village',
  `level_label` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '层级显示名',
  `province` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '省',
  `city` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '市',
  `county` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '县/区',
  `town` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '乡镇',
  `verified` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '机构资料是否核实：0否1是',
  `current_operation_verified` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '当前执业状态是否核实：0否1是',
  `verification_scope` VARCHAR(255) NOT NULL DEFAULT '' COMMENT '核实范围说明',
  `evidence_as_of` VARCHAR(16) NOT NULL DEFAULT '' COMMENT '证据截至日期',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `deleted_at` DATETIME NULL DEFAULT NULL COMMENT '软删除时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_org_id` (`org_id`),
  KEY `idx_level` (`level`),
  KEY `idx_city` (`city`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='医疗机构表';
```

索引说明：`uk_org_id` 机构编码唯一（scenario 患者/床位/人员均以 `org_id` 关联）；`idx_level` 支撑医共体层级树排序；`idx_city` 按地域筛选。

### 2.2 科室表 `departments`

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |
|---------|-----------|------|------|------|
| 科室 | dept_id | String | 是 | 科室编码（如 `icu`，跨机构复用编码） |
| 机构 | org_id | String | 是 | 所属机构 |
| 科室名 | name | String | 是 | 如 `重症医学科` |
| 父科室 | parent_dept_id | String | 否 | 上级科室，支撑科室树 |
| 依据时间 | evidence_as_of | String | 否 | 证据截至日期（如 `2023-12-15`） |

```sql
CREATE TABLE `departments` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `org_id` VARCHAR(32) NOT NULL COMMENT '所属机构编码',
  `dept_id` VARCHAR(32) NOT NULL COMMENT '科室编码，如 icu',
  `name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '科室名称',
  `parent_dept_id` VARCHAR(32) NULL DEFAULT NULL COMMENT '父科室编码（树形）',
  `evidence_as_of` VARCHAR(16) NOT NULL DEFAULT '' COMMENT '证据截至日期',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_org_dept` (`org_id`, `dept_id`),
  KEY `idx_parent` (`org_id`, `parent_dept_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='科室表';
```

### 2.3 机构成员表 `organization_members`

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |
|---------|-----------|------|------|------|
| 成员 | member_id | String | 是 | 成员编码（如 `weiyuan-cao-yu`） |
| 机构 | org_id | String | 是 | 所属机构 |
| 姓名 | name | String | 是 | 姓名 |
| 职称 | title | String | 否 | 主任医师 / 副主任护师等 |
| 职业 | profession | String | 否 | 医师 / 护理 |
| 科室 | dept_id | String | 否 | 所属科室编码 |
| 当前值班/工作区 | work_areas | JSON | 否 | 工作区（reception/ward/field） |
| 依据时间 | evidence_as_of | String | 否 | 人员资料截至 |

```sql
CREATE TABLE `organization_members` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `member_id` VARCHAR(64) NOT NULL COMMENT '成员编码',
  `org_id` VARCHAR(32) NOT NULL COMMENT '所属机构编码',
  `name` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '姓名',
  `title` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '职称',
  `profession` VARCHAR(16) NOT NULL DEFAULT '' COMMENT '职业：医师/护理',
  `dept_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '所属科室编码',
  `work_areas` JSON NULL COMMENT '工作区数组：reception/ward/field',
  `evidence_as_of` VARCHAR(16) NOT NULL DEFAULT '' COMMENT '人员资料截至',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_member_id` (`member_id`),
  KEY `idx_org_dept` (`org_id`, `dept_id`),
  KEY `idx_profession` (`profession`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='机构成员表';
```

### 2.4 机构权限范围表 `organization_permissions`

| 前端展示 | 数据库字段 | 类型 | 必填 | 说明 |
|---------|-----------|------|------|------|
| 权限 | perm_id | String | 是 | 权限编号 |

| 项目 | 内容 |

| 接口名称 | 获取机构列表 |

### 3.2 新增机构

| 项目 | 内容 |
|------|------|
| 接口名称 | 新增机构 |
| 请求方法 | POST |
| 请求路径 | `/api/v1/organizations` |
| 接口描述 | 维护机构：新增医共体成员机构 |
| 前端调用时机 | 机构维护「新增机构」 |
| 前端渲染对应 | 机构列表新增行 |

**Body 参数：**

| 字段名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| orgId | String | 是 | 机构编码 | xindian |
| name | String | 是 | 机构全称 | 威远县新店镇卫生院 |
| shortName | String | 否 | 简称 | 新店镇卫生院 |
| level | String | 是 | 层级 | township |
| levelLabel | String | 否 | 层级显示名 | 乡镇卫生院 |
| province / city / county / town | String | 否 | 省市区乡镇 | 四川省 / 内江市 / 威远县 / 新店镇 |
| verified | Boolean | 否 | 是否已核实 | false |

**请求示例：**

```http
POST /api/v1/organizations HTTP/1.1
Authorization: Bearer {token}
Content-Type: application/json

{
  "orgId": "xindian",
  "name": "威远县新店镇卫生院",
  "shortName": "新店镇卫生院",
  "level": "township",
  "levelLabel": "乡镇卫生院",
  "province": "四川省",
  "city": "内江市",
  "county": "威远县",
  "town": "新店镇",
  "verified": false
}
```

**响应示例（成功）：**

```json
{ "code": 200, "message": "success", "data": { "orgId": "xindian" } }
```

**错误码：**

| code | 含义 |
|------|------|
| 200 | 成功 |
| 400 | 参数校验失败（orgId/name/level 为空） |
| 401 | 未认证 |
| 409 | 机构编码已存在 |

## 4. 状态与枚举值

### 4.1 机构层级 `level`

| code（存储） | label（显示） | 链上位置 |
|-------------|--------------|---------|
| `center` | 中心医院 | 中心 |
| `city` | 市级医院 | 市级 |
| `county` | 县级医院 | 县级 |
| `township` | 乡镇卫生院 | 乡镇 |
| `village` | 村卫生室 | 村级 |

### 4.2 权限数据范围 `scope`

| code | 显示 | 说明 |
|------|------|------|
| `LOCAL` | 本院 | 仅本机构数据 |
| `PARTNER` | 协作医院 | 协作同级机构 |
| `LOWER` | 下级医院 | 下级/基层机构 |

## 5. 交互与边界说明

- **层级链**：前端按 `村级→乡镇→县级→市级→中心` 顺序渲染机构层级链，`level` 决定顺序；机构新增后需落在正确层级。
- **科室编码语义**：`dept_id` 为跨机构通用编码（`icu`/`emergency`/…），同一编码在不同机构含义一致（`scenario.json` 患者/床位以 `departmentId` 直接引用）。
- **无科室机构**：乡镇/村级机构 `departments` 可能为空，前端以「卫生室（演示工作单元）」降级展示；接口返回空数组即可。
- **资料核实**：`verified`/`currentOperationVerified` 区分「历史资料已核实」与「当前执业状态已核实」；`船石村卫生室` 为「历史来源、现状待核」，前端据此显示警示徽标。
- **成员去敏**：机构成员仅返回姓名、职称、职业、科室，不含联系方式与实时出诊状态。
